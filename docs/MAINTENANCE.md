# 유지보수와 운영 확인

기능 변경·릴리스·데이터 전환 시 다시 확인할 경계를 유지합니다. 아래 미검증 항목은 현재 장애를 확인했다는 뜻이 아닙니다. 실제 Firebase 전환은 [전환 절차](FIREBASE_CUTOVER.md), 개발 검사와 배포 경로는 [개발 가이드](../DEVELOPMENT.md)를 따릅니다.

| 경계 | 확인할 내용 |
| --- | --- |
| 배포 근거 | 검사한 SHA와 main·mirror·실제 배포의 source SHA를 연결하고 한국어/영어 HTTP·화면을 확인합니다. 로컬·CI 성공을 운영 반영으로 대신하지 않습니다. |
| Firestore | [규칙·인덱스·TTL](FIRESTORE_RULES.md)의 적용 상태와 실제 쿼리를 확인합니다. 정의 파일만으로 인덱스 READY나 TTL 물리 삭제를 판단하지 않습니다. 만료 정리의 updateTime 충돌은 갱신 문서를 보호하지만 같은 배치도 남길 수 있어 실패 알림과 재실행을 확인합니다. |
| 요청 제한 | 프로세스 단위 제한은 전체 인스턴스의 총량 제한이 아닙니다. 학교 NAT의 공유 IP도 429를 받을 수 있으므로 실제 거부·DB/Auth 사용량으로 판단하고 인증·소유자 검사를 유지합니다. |
| 입력·프록시 | canonical `/api/*`의 본문 바이트 상한과 호스팅 프록시의 버퍼링·업로드 시간 제한을 구분합니다. localized API와 실제 HTTPS·Origin·forwarded host·CSP도 별도로 확인합니다. |
| 브라우저 저장소 | 저장소 차단 시 서버 저장 성공과 로컬 토큰·초안 보존 실패를 구분합니다. 메모리만으로 보존한 값은 새로고침·탭 종료 후 복원되지 않습니다. 시간표·졸업요건·Meet의 기존 키·형식·TTL을 유지하며 다른 origin 간 자동 이전을 가정하지 않습니다. |
| 홈 입력 준비 | 검색은 데이터 조회 경계 밖에서 SSR·hydration합니다. 대시보드는 공지 요약·서비스 공지·학사일정·공휴일·학식·셔틀·특별 운행의 7개 병렬 작업과 cold 스트리밍·warm 최대 20ms 준비 대기를 사용합니다. hydration 전 입력·제출·초기화·초점, 식당/교통 선택과 노선별 다음 편을 확인합니다. |
| 초기 성능 | 초기 JS·폰트 비용, 실제 기기의 CWV/INP·동시 접속·장시간 안정성은 별도 확인 대상입니다. 이미지 팝업의 warm 실험을 전체 cold 성능으로 확대하지 않습니다. 측정 조건과 보류한 과제는 [성능 가이드](../PERFORMANCE.md)를 따릅니다. |
| 공개 공지·팝업 | 공개 배너 읽기에는 1초 예산과 캐시가 적용됩니다. 첫 응답의 빈 목록·이전 본문 관측은 정상 데이터·성능 결과와 구분합니다. API와 SSR·클라이언트 복구를 함께 관찰합니다. 이 간헐적 fallback의 후속 분석은 보류된 상태이며 해결됐다고 가정하지 않습니다. 닫기·오늘 숨김·다른 dialog 양보·초점 복귀·숨긴 이미지 요청 0건을 유지합니다. |
| 원격 데이터·캐시 | 1MiB를 초과하는 Pages raw JSON은 Next Data Cache에서 제외합니다. 작은 파일의 force-cache, 60초 manifest·버전별 Promise 캐시와 무결성 검사는 유지합니다. 이 정책은 다운로드 총량을 줄이지 않으므로 cold 재다운로드·파싱·최신성을 확인합니다. [데이터 가이드](PUBLIC_DATA_FIREBASE.md)와 [Pages 캐시 정책](CRAWL_DATA_PAGES.md#앱-런타임-캐시)을 따릅니다. |
| 원문 데이터 계약 | 저상버스 unknown, 도서관 XML 순서·좌석 합계, 같은 강의 ID의 시간·장소 충돌, 식단 주차·날짜 범위·시간대는 실제 원문과 대조합니다. 조회 실패를 휴무·운행 종료로 바꾸거나 확인되지 않은 값을 임의 보정하지 않습니다. 특별 셔틀 시간표는 별도 선택·기본 시간표 복귀·적용 날짜/노선 조건을 확인합니다. |
| 외부 서비스 | 실제 Kakao SDK·허용 도메인·쿠키/CSP·지도 재선택, 날씨, 셔틀·대중교통·도서관 공급자 가용성을 확인합니다. 쿠키를 모든 지도 실패의 원인으로 단정하지 않습니다. 외부 장애에서는 기존 정적 시간표·검색·시설 목록 등 대체 경로를 보존합니다. |
| 관리자 계정 | 폐기 여부를 확인한 Firebase ID token과 서버 `ADMIN_UIDS`를 사용합니다. UID 대소문자를 보존하며 이메일 목록을 권한 판정에 쓰지 않습니다. 실제 허용 계정 조회, 비로그인 401·미등록 UID 403·설정 누락 503과 revoke 후 거부를 확인합니다. |
| 환경·공개 키 | [환경 등록](ENVIRONMENT_REGISTRATION.md)의 이름·형식과 Production/Preview의 프로젝트·데이터·권한 격리를 확인합니다. 서버 비밀값의 저장 유형·적용 범위를 대조합니다. 공개 Firebase 키의 referrer 제한을 바꾸기 전 서버 메일 등 기존 소비자를 확인하고 재빌드·열린 탭·서비스워커 전환도 검사합니다. |
| 실제 저장·발송 | 문의·신고·공유·Meet의 운영 DB 왕복과 지정 테스트 메일함 수신·만료는 에뮬레이터 성공과 별개입니다. 실제 사용자 데이터나 일반 사용자에게 발송해 시험하지 않습니다. 실제 인증·접수·메일·푸시 검증의 승인 범위를 먼저 정합니다. |
| 알림·중복 방지 | 금·토 발송 제외와 발송 lock·복구 계약을 유지합니다. 부분 발송·timeout 후 lock 자동 삭제나 전체 재발송을 하지 말고 발송 범위를 확인합니다. 실제 기기의 FCM 등록·백그라운드/종료 수신·클릭·해지를 모의 전송과 구분합니다. |
| 번역·비용 | [번역 가이드](CONTENT_TRANSLATION.md)의 공개 필드 제한·숫자/날짜 검증·일일 예산·캐시·원문 복구를 유지합니다. 학사 용어 품질, 실제 quota·청구·TTL 삭제·Storage 권한을 운영에서 확인하며 한도 소진 시험은 하지 않습니다. |
| 관측·개인정보 | Sentry의 데이터 제거·IP 저장·보존 기간·경보 전달·외부 source fetch와 TLS 검증 정책을 운영자가 확인합니다. 브라우저 오류 수신 성공만으로 개인정보 정책 적용을 판정하지 않습니다. 계정 ID·설정 화면·사용자 이벤트 원문을 공개 기록에 넣지 않습니다. |
| 검색·공유 노출 | metadata·robots·sitemap 검사와 실제 Search Console 색인·검색/AI 인용·외부 OG 캐시는 별개입니다. [검색 가이드](SEARCH_INDEXING_GUIDE.md)의 운영 절차를 따릅니다. |
| 브라우저·Android | 실제 iOS Safari·Android Chrome·desktop Firefox/Safari, OS 키보드·200% 확대·VoiceOver/TalkBack/NVDA, PWA 갱신을 확인합니다. 웹 검사와 Android 빌드·서명·Digital Asset Links·실기기·스토어 승인은 별도이며 [TWA 가이드](TWA_ANDROID.md)를 따릅니다. |

룸메이트의 인증·보존·중지·실계정 조건은 [룸메이트 운영](ROOMMATES.md), 공지·팝업의 게시와 이미지 정책은 [관리자 가이드](ADMIN_CONTENT.md)를 기준으로 합니다. Firebase 생산자·소비자 검증과 복구가 완료되기 전에는 Pages·원본 MD/JSON·구형 아이콘 URL을 제거하지 않습니다.

검증 기록에는 실행 시각·SHA·환경·명령과 통과/실패/미실행을 남깁니다. 공개 문서는 계약·재현 조건·미해결 게이트를 유지하고 개인 경로·비밀값·사적 백업·미가림 캡처·실행 중간 로그는 포함하지 않습니다.
