# 유지보수와 운영 확인

2026-10-26 M3 서비스 구현 기준. 현재 소스에 적용된 기능과 운영에서 다시 확인해야 할 경계를 유지합니다. 아래 미검증 항목은 현행 장애를 확인했다는 뜻이 아닙니다. 배포 준비의 실행 기준은 [출시 체크리스트](RELEASE_CHECKLIST_2026-10-26.md)를 함께 확인합니다.

| 경계 | 변경·배포 시 확인할 내용 |
| --- | --- |
| 배포 근거 | 검사한 SHA와 실제 배포 SHA·URL을 연결하고 한국어/영어 HTTP·화면을 확인합니다. 로컬·CI 성공만으로 운영 반영을 판단하지 않습니다. |
| Firestore | [규칙·인덱스·TTL](FIRESTORE_RULES.md)의 배포 상태와 해당 쿼리를 확인합니다. 인덱스 정의 파일은 콘솔의 READY 상태를 대신하지 않습니다. 정리 작업의 updateTime 전제조건 실패는 갱신된 문서를 보호하지만 같은 배치의 만료 문서도 남길 수 있어 로그·실패 알림과 재실행을 확인합니다. |
| 요청 제한 | 프로세스 단위 제한은 서버 인스턴스·재배포를 가로지르는 총량 제한이 아닙니다. 학교 NAT 등 공유 IP의 정상 요청도 429를 받을 수 있으므로 실제 거부·DB/Auth 사용량으로 한도를 판단합니다. 인증·소유자 검사를 유지합니다. |
| 입력·프록시 | canonical `/api/*`의 본문 바이트 상한과 호스팅 프록시의 버퍼링·업로드 시간 제한을 구분합니다. localized API와 실제 플랫폼의 body/time 제한은 별도 확인합니다. |
| 브라우저 저장소 | 저장소 차단 시 서버 저장 성공과 로컬 토큰·초안 보존 실패를 구분합니다. 메모리 보존만 가능한 값은 새로고침·탭 종료 후 복원되지 않습니다. |
| 홈 입력 준비 | 두 언어의 검색창은 데이터 조회 경계 밖에서 SSR·hydration합니다. 대시보드는 공지 요약·서비스 공지·학사일정·공휴일·학식·셔틀 시간표·특별 운행의 7개 병렬 작업을 기다립니다. 첫 cold의 스트리밍과 warm에서 최대 20ms 준비 대기를 유지합니다. hydration 전 입력·제출 값·초기화·포커스, 식당/교통 선택과 노선별 다음 편을 확인합니다. 이전 4조회 fixture의 성능을 현재 M3 실데이터 결과로 승계하지 않습니다. [성능 가이드](../PERFORMANCE.md)와 [과거 측정 기록](DESIGN_UX_AUDIT_2026-10-18.md)을 따릅니다. |
| 외부 서비스 | 실제 Kakao SDK·도메인 제한·지도 재선택, 날씨, 학생 메일, 푸시는 mock·viewport 검사와 별도로 확인합니다. 발송·권한 변경은 해당 운영 절차를 따릅니다. |
| 원격 데이터·캐시 | Pages 버전 JSON의 raw 크기가 1MiB를 초과하면 Next Data Cache에서 제외하고, 작은 파일의 force-cache와 기존 60초 manifest·버전별 Promise 캐시를 유지합니다. 원문 크기와 Base64 직렬화된 캐시 경고 크기를 혼동하지 않습니다. 이 정책은 원본 network 총량을 줄이지 않으므로 cold instance의 재다운로드·파싱과 upstream 최신성은 계속 확인합니다. [캐시 정책](CRAWL_DATA_PAGES.md#앱-런타임-캐시)과 [성능 측정](../PERFORMANCE.md)을 따르며 과거 경고·warm 수치를 현재 cold 상태로 대신하지 않습니다. |
| 원문 데이터 계약 | 서울 버스 저상 여부의 unknown 표현, 도서관 XML 순서·좌석 합계의 의미, 같은 강의 ID의 시간·장소 충돌, 식단 주차·응답 날짜 범위·시간대는 실제 원문과 대조합니다. 확인되지 않은 좌석 합계 등을 계산 오류로 단정하거나 임의로 보정하지 않습니다. |
| 관리자 계정 | 현재 관리자 인증은 폐기 여부를 확인한 Firebase ID token과 서버 전용 `ADMIN_UIDS`를 사용합니다. UID의 대소문자를 보존하며 이메일 목록은 권한 판정에 사용하지 않습니다. 해당 Firebase 프로젝트에서 소유자를 확인한 UID를 코드 배포 전에 등록하고 새 배포에 반영합니다. 유효한 token 검증 후 설정이 비어 있으면 503, 미등록 UID는 403입니다. Production·Preview·Development의 프로젝트·UID 분리와 기존 관리자 접근을 실제 환경에서 확인합니다. |
| 환경·공개 키 | [환경 등록](ENVIRONMENT_REGISTRATION.md)의 이름·형식을 따르고 Production/Preview의 프로젝트·데이터 격리를 확인합니다. 브라우저와 서버 메일이 공유하는 Firebase 키에 referrer 제한을 추가하면 서버 요청이 실패할 수 있으므로 용도와 기존 소비자를 먼저 확인합니다. 키 교체는 재빌드·열린 탭·서비스워커 전환까지 검증합니다. |
| 알림·중복 방지 | 금·토 발송 제외 등 기존 정책, 발송 lock·복구 절차는 [개발 가이드](../DEVELOPMENT.md)를 따릅니다. batch 진행 건수는 대상별 안전한 재개를 보장하지 않습니다. 부분 발송·timeout 후 lock을 자동 삭제하거나 전체 재발송하지 말고 실제 발송 범위부터 확인합니다. 소급 발송은 별도 정책 변경입니다. |
| Android | 웹·정적 TWA 검사와 Android 빌드·서명·Digital Asset Links·실제 단말 연결·스토어 승인은 각각 다른 검증입니다. [TWA 가이드](TWA_ANDROID.md)의 출시 조건을 확인합니다. |

룸메이트의 인증·보존·중지·실계정 및 실기기 조건은 [룸메이트 운영 문서](ROOMMATES.md)를 기준으로 합니다. UI의 미해결 사항은 [디자인·사용성·성능 점검](DESIGN_UX_AUDIT_2026-10-18.md)에 유지합니다.

검증 결과는 실행 시각·SHA·환경·명령과 `통과 / 실패 / 미실행`을 남깁니다. 외부 서비스 제한이나 원본 자료 부재로 생략한 항목도 함께 기록하며, 계정·인증값·개인 경로·미가림 캡처는 공개 근거에 포함하지 않습니다.
