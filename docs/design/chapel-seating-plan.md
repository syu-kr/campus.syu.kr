# 채플 좌석 조회 구현 계획

대강당의 구역과 좌석 번호를 입력하면 좌석 위치와 사진상의 줄을 확인하는 기능을 만든다. 학과별 배정과 개인의 학교 배정 정보를 수집하지 않는다. 사용자가 확인한 현재 배치, 2023년 배치도, 사진에서 생략된 좌석이 표시된 과거 공식 도면을 구분해 사용한다.

1차 기능을 구현했다. 사진에서 확인한 1,282석과 나·다열 앞쪽 복원 104석의 번호·줄 경계를 대조해 1,386석의 위치를 제공한다. 가·라열의 미확인 번호 12개는 위치를 추정하지 않는다. [좌석 데이터 검수](chapel-seating-data.md)에 전체 줄 경계와 근거를 기록했다. 아래 내용은 구현 계약과 후속 확장 기준이며, 현장 실측·실기기·실제 배포 검증은 로컬 검사와 구분한다.

## 합의한 요구사항

| ID | 확정 사항 | 구현 또는 검증 기준 |
| --- | --- | --- |
| R01 | 대강당 1층 가·나·다·라열의 구역·좌석 번호 조회 | 존재가 확인된 좌석을 조회 대상으로 관리하고 위치 검수 상태를 구분한다. |
| R02 | 학과 정보 제외 | 학과 이름·색상 구획·학과별 배정 범위를 화면과 좌석 데이터에 넣지 않는다. |
| R03 | 좌석·줄·구역 명칭은 제공된 사진과 동일 | 사진의 줄 표기를 유지하며 물리적으로 앞에서 몇 번째인지와 혼동하지 않는다. |
| R04 | 좌석 번호 표찰은 등받이 뒤에 있음 | “해당 좌석 등받이 뒤의 번호 표찰을 확인하세요.”라고 안내한다. |
| R05 | 나·다열 1~52번은 실제로 존재하며 사진에서 생략됨 | 각각 52석을 조회 대상에 포함한다. 자료 대조로 위치 복원·검수를 완료했다. |
| R06 | 출입문 위치는 사진과 동일 | 지도상의 위치 표시는 가능하다. 현재 개방 여부나 통로의 통행 가능성까지 확인된 것으로 간주하지 않는다. |
| R07 | 별도 개방 문·통제 방향·확인 담당 정보가 없음 | 해당 운영 정보의 수집·관리 기능과 확인 담당자를 임의로 만들지 않는다. |
| R08 | 혼잡 양상은 확인할 수 없음 | 혼잡 수집·예측·실시간 한산한 경로 안내를 제외한다. |
| R09 | 이 기기에 좌석 저장·변경·삭제를 1차에 포함 | 사용자가 명시적으로 저장하며 현재 학교 배정과 구분한다. |
| R10 | 서비스 검색에 등록 | 채플·대강당·좌석 및 대응 영어 검색어로 진입 가능하게 한다. |
| R11 | 추후 출입문·동선 안내로 확장 | 좌석 ID·줄 안 순서와 통로 연결을 분리하고 경로 계산은 후속 단계에서 구현한다. |
| R12 | 계획에 따른 1차 구현과 검증 | 좌석 복원·검수를 먼저 수행하고 기능 구현·테스트·모바일 브라우저 검증까지 완료한다. |

R01~R11은 사용자 요구 및 확인 답변을 반영한다. 아래의 데이터 형식·파일 배치·오류 처리·검수 방법은 이 요구를 수행하기 위한 설계다. 범위를 넓히는 기능을 추가하려면 별도로 필요성과 근거를 검토하고 추가 여부를 확인한다.

## 초기 기능과 제외 범위

한국어 주소는 `/campus/chapel-seats`, 영어 주소는 `/en/campus/chapel-seats`로 제안한다. 메뉴 이름은 “채플 좌석 찾기”로 한다. 기존 캠퍼스 메뉴, 데스크톱 내비게이션, 캠퍼스 지도의 대강당 안내, 서비스 검색에서 진입한다.

초기 기능은 구역·번호 검색, 전체 위치 강조, 선택한 줄의 확대와 주변 번호, 글로 된 위치 설명, 기기 내 저장, 한국어·영어 UI다. 무대 방향과 출입문 위치는 공간 파악을 돕는 정적 요소로 표시한다. 출입문 추천과 경로 계산은 후속 기능이다.

로그인, 학교 계정 연동, 출석 처리, 개인별 좌석 배정 조회, 좌석 예약·변경, 좌석 점유 현황, 2층 UI, GPS 추적, 새 제보 시스템, 공유 링크, 오프라인 재접속 보장은 초기 범위에 포함하지 않는다. 다른 층을 추가할 수 있도록 데이터에 장소·층 식별자는 둔다.

확인한 원본 이미지는 2101×3013이다. 이미지가 고해상도라는 사실은 모든 번호가 판독 가능하거나 최신 배치 전체를 담았다는 뜻은 아니다. 학과명이 포함된 원본 이미지를 사용자 화면의 배경으로 배포하지 않고, 검수한 좌석 데이터로 새 지도를 그린다.

상충하는 부분은 현재 사진에 보이는 좌석을 우선한다. 과거 도면은 사진에서 생략된 부분을 보완하는 근거로만 사용한다. 동일하다는 가정으로 두 도면의 좌표나 줄 번호를 섞지 않는다.

### 생략된 나열과 다열 앞 네 줄

과거 도면은 휠체어 구역을 01줄로 표시하고, 나·다열의 1~52번을 그 뒤 네 줄에 13석씩 배치한다. 현재 사진에서는 53~65번이 05줄, 66~78번이 06줄에 대응한다. 아래 표는 두 자료의 공통 번호·줄·좌우 순서를 대조해 반영한 복원 결과이며 현장 실측 결과가 아니다.

| 각 구역의 번호 | 현재 사진 줄 체계 | 상태 |
| --- | --- | --- |
| 1~13 | 01줄 | 존재 확인, 자료 대조와 도식 좌표 검수 완료 |
| 14~26 | 02줄 | 존재 확인, 자료 대조와 도식 좌표 검수 완료 |
| 27~39 | 03줄 | 존재 확인, 자료 대조와 도식 좌표 검수 완료 |
| 40~52 | 04줄 | 존재 확인, 자료 대조와 도식 좌표 검수 완료 |
| 53~65 | 05줄 | 현재 사진과 번호·줄 경계 대조 완료 |
| 66~78 | 06줄 | 현재 사진과 번호·줄 경계 대조 완료 |

복원 작업은 53번 이후 공통 좌석의 좌우 순서와 줄 경계를 비교하고, 두 도면의 공통 기준점으로 지도 위치를 맞춘다. 번호, 줄, 줄 안 순서, 좌표를 각각 검수하고 보완 출처를 기록한다. 과거 휠체어 구역을 현재 지도의 추가 줄로 자동 삽입하지 않는다.

가·라열 앞줄 등에도 그림에서 보이지 않는 번호가 있으므로, 나·다열의 생략 확인을 다른 구역 전체로 확대 적용하지 않는다. 상단의 `가·라 1~361`, `나·다 1~338`은 점검할 번호 범위이며 모든 번호의 존재·위치를 보증하는 목록이 아니다. 범위 합계 1,398과 과거 PDF의 1층 1,394석 표기도 다르므로 총 좌석 수를 미리 확정하거나 그 수에 맞춰 데이터를 채우지 않는다.

## 화면과 검색 동작

### 기본 흐름

1. 페이지에 1층 지원 범위, 구역 선택, 좌석 번호 입력, 좌석 번호 확인 방법을 표시한다.
2. 구역은 가열·나열·다열·라열 중 명시적으로 선택한다. 번호만으로 구역을 추측하지 않는다.
3. “위치 찾기” 또는 Enter로 조회한다. 숫자 키패드를 제공하고 처음부터 숫자 입력칸에 자동 포커스해 모바일 키보드를 열지 않는다.
4. 결과 카드에 층·구역·번호·사진상 줄·표찰 확인 방법을 표시한다. 전체 지도에는 선택 좌석과 구역을 강조하고 해당 줄의 상세 보기를 제공한다.
5. “전체 보기”, “좌석 확대”, 확대·축소 조작으로 전체 위치와 주변 번호를 오갈 수 있게 한다.
   확대 상태에서는 마우스·한 손가락 드래그, 방향키 또는 이동 버튼으로 지도를 움직인다. 이동 범위는 도식 안으로 제한하고 확대·축소는 현재 보는 중심을 유지한다. 전체 보기와 좌석 확대는 각각 전체 배치와 검색 좌석으로 위치를 되돌린다. 전체 보기 상태에서는 페이지의 기본 터치 스크롤을 유지한다.
6. 사용자가 “이 기기에 저장”을 누르면 검수된 검색 결과를 저장한다.

모바일은 검색, 결과 설명, 전체 위치, 줄 상세, 저장 순서로 배치한다. 검색 직후 전체 배치에서 선택 위치를 보여주며 “좌석 확대”로 주변 번호를 확인한다. 확대 중에도 무대 방향·구역·줄을 표시한다. 지도 옆에 줄 번호를 제공하고, 작은 전체 지도에서는 간격이 겹치지 않도록 주요 줄과 선택한 줄을 표시한다. 좌우는 “객석에서 무대를 바라보는 기준”으로 고정한다. `05줄`을 해당 구역의 “앞에서 다섯 번째 줄”로 자동 치환하지 않는다. 출입문에 이름이 필요하면 위치 설명을 쓰고 현장에 없는 공식 문 번호를 만들지 않는다.

번호는 문자열 입력을 정규화한 뒤 양의 정수인지 검증한다. 앞뒤 공백과 앞자리 0은 허용하고 `003`과 `3`을 동일하게 처리한다. 음수·소수·지수 표기·숫자 뒤 임의 문자를 숫자의 일부만 읽어 허용하지 않는다. 초기 UI는 구역과 번호의 두 필드로 고정하며 자유문장 파서는 추가하지 않는다.

입력값 변경 시 이전 결과의 선택 강조와 저장 가능 상태를 해제한다. 조회 실패 시 이전 좌석을 현재 결과처럼 남기지 않는다. 다른 좌석을 검색했다고 이미 저장된 좌석이 자동으로 바뀌지는 않는다.

### 조회 결과 상태

| 상태 | 조건 | 표시 및 동작 |
| --- | --- | --- |
| 조회 전 | 아직 유효한 검색을 실행하지 않음 | 입력 안내와 전체 구조 표시 |
| 입력 오류 | 구역 미선택, 빈 번호, 잘못된 숫자 형식 | 해당 필드와 수정 방법 안내 |
| 위치 확인됨 | 존재 확인 및 위치 검수 완료 | 지도 강조·줄 상세·저장 허용 |
| 위치 미확인 | 존재는 확인됐으나 줄·좌표 검수 미완료 | “좌석은 존재하지만 현재 위치 안내를 준비 중입니다.”, 추정 좌표와 저장 버튼 미제공 |
| 도면에서 확인되지 않음 | 등록 범위 안의 번호지만 존재 여부가 불명확 | 도면에서 확인할 수 없다고 안내하고 가까운 번호로 대체하지 않음 |
| 없는 번호 | 해당 번호가 없다는 근거를 확보함 | 존재하지 않는 번호임을 안내 |
| 지원 범위 밖 | 미지원 구역·층 또는 데이터의 점검 범위 밖 | 1층 지원 범위와 입력 재확인 안내 |

일반 결과에서 “배정 확인 완료”, “출석 가능한 좌석” 같은 표현을 사용하지 않는다. “검색한 좌석”과 “저장한 좌석”을 사용하며 실제 학교 배정은 사용자가 확인한다.

| 줄 | 구역 안에서 고유한 줄 ID, 사진상 줄 표기, 해당 줄의 좌석 ID 순서 | 줄 번호와 좌석 번호를 분리 |
| 좌석 | 좌석 ID, 구역 참조, 번호, 존재 상태, 위치 검수 상태, 근거 참조, 위치를 아는 경우 줄 참조·좌표 | 정확한 조회와 불확실한 위치의 오안내 방지 |
| 문 위치 | 문 ID, 좌표, 위치 설명 | 1차 지도 표시와 후속 통로 연결의 기준 |

좌석 ID 예시는 `grand-auditorium:1:ga:123`이다. 줄 ID에는 구역을 포함해 다른 구역의 같은 줄 번호와 충돌하지 않게 한다. 표시용 번호와 고유 ID를 구분하며 번호가 재배정되는 변경에는 `layoutVersion`을 올린다. 현재 캠퍼스 지도의 `grand-auditorium` 장소 ID를 재사용한다.

줄의 좌석 ID 목록을 좌우 순서의 기준으로 삼고, 같은 순서를 좌석 객체마다 중복 관리하지 않는다. 번호의 크기나 일정한 좌석 수 공식으로 줄과 좌표를 추정하지 않는다. 같은 데이터에서 전체 지도·줄 상세·텍스트 결과를 생성한다.

존재 상태와 위치 검수 상태는 분리한다. 현재 구현은 검수한 좌석만 `SEATS`에 넣고, 존재 미확인 번호는 `UNCONFIRMED_NUMBERS`에 별도로 기록해 조회 결과 상태를 구분한다. 나·다열 1~52번은 자료 대조 검수가 끝나 `restored` 출처로 포함했다. 줄이나 좌표를 모르면 형식을 맞추기 위해 임의 줄이나 `(0, 0)`을 넣지 않는다. 검수 완료 좌석에는 유효한 줄 참조·순서·좌표를 모두 요구한다. “위치 검수 완료”는 자료 전사와 복원 근거를 확인했다는 뜻이며, 개발자가 현장 실측을 했다는 뜻으로 사용하지 않는다.

지도 좌표는 SVG의 내부 좌표로 관리한다. 이는 지리 좌표나 실제 미터 단위가 아니다. 후속 단계에서 거리가 필요하면 별도의 실측 정보나 검증된 축척을 사용한다.

## 기기에 좌석 저장

단일 저장 좌석을 `localStorage`의 기능 전용 키로 관리한다. 값에는 저장 형식 버전, 장소·층·구역·좌석 식별자, 도면 버전, 저장일·마지막 확인일을 포함한다. 좌표·학과·이름·학번·학교 인증 정보는 저장하지 않는다.

- 검색과 저장을 분리하고 저장·교체·삭제 시 결과를 명확하게 알린다.
- 입력값 또는 조회 결과가 바뀌면 이전 저장·삭제 메시지를 지워 새 검색 결과에 과거 행동의 성공을 표시하지 않는다.
- 재방문 시 “저장한 좌석”과 저장일을 표시한다. 현재 배정이라고 자동 선언하지 않는다.
- 동일 도면 버전이면 최신 좌석 목록에서 식별자를 다시 조회해 표시한다.
- 도면 버전이 다르면 과거 좌표를 재사용하지 않는다. 현재 데이터로 재조회하고 사용자가 저장 좌석을 다시 확인한 뒤 저장 버전을 갱신한다.
- 위치가 미확인으로 바뀌거나 좌석을 찾을 수 없으면 지도 강조를 중단한다. 저장한 번호는 사용자가 수정·삭제할 수 있게 남긴다.
- 저장소 접근 제한, 용량 오류, 손상된 JSON, 알 수 없는 형식 버전은 기본 조회를 막지 않는다. 현재 창에서만 유지되는 상태를 영구 저장 성공으로 표시하지 않는다.
- 삭제는 이 기능의 키에만 적용한다. 사이트의 다른 저장 데이터는 지우지 않는다.

학기 변경 시 학교의 배정 좌석을 다시 확인하도록 안내한다. 정확한 현재 학기를 판정하는 연동이 없는 1차에서는 학기 변경을 자동 감지하거나 배정을 자동 갱신한다고 약속하지 않는다. 좌석 입력·저장값을 별도 분석 이벤트, URL, 서버 저장소에 전송하는 기능은 추가하지 않는다.

## 접근성과 다국어

검색만으로 모든 지원 좌석에 접근할 수 있게 해 작은 좌석 클릭을 필수로 만들지 않는다. 천 개 이상의 좌석을 각각 Tab 이동 대상으로 만들지 않고, 입력·지도 조작·결과 설명·저장 버튼을 중심으로 키보드 흐름을 구성한다.

선택 좌석은 색상뿐 아니라 전체 지도에서는 원형 표시와 번호, 확대 지도에서는 외곽선과 체크, 줄 상세에서는 체크로 표시한다. 각 지도 모드의 범례를 실제 표시와 맞춘다. 좌석 자체의 크기와 모양은 선택 여부에 관계없이 통일한다. 검색 결과와 지도 상태를 글로 제공하고 검색 성공·오류·저장 결과는 과도한 반복 없이 보조기기에 전달한다. 결과로 포커스를 강제 이동시키는 대신 상태 알림과 명확한 결과 영역을 제공한다.

버튼은 모바일에서 누르기 쉬운 크기로 구성한다. [W3C 조작 크기 안내](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)의 최소 크기·간격·동등한 대체 조작 조건을 검토한다. 드래그나 핀치를 제공하더라도 [드래그 대체 조작](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)을 제공하며, 핀치만으로 확대하게 하지 않는다. [복잡한 이미지의 텍스트 설명](https://www.w3.org/WAI/tutorials/images/complex/)과 [상태 메시지](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)도 적용한다.

UI 문구는 기존 한국어·영어 사전에 추가한다. 영어에서도 `가`, `나`, `다`, `라`와 원래 좌석 번호·줄 순서는 유지한다. 링크는 현재 언어를 보존하며, 실제 좌석 표기를 기계 번역한 값으로 대체하지 않는다.

## 후속 출입문과 동선 안내

확장 구조는 `선택한 문 → 통로 연결 지점 → 좌석줄 진입점 → 좌석`이다. 문·통로·좌석줄 진입점의 연결을 좌석의 화면 좌표와 분리한다. 1차에는 장소·문·구역·줄·좌석 식별자를 준비하고 경로 엔진이나 사용하지 않는 운영 시스템을 미리 구현하지 않는다.

후속 데이터에는 통로 노드, 연결 구간, 줄의 접근 가능한 진입점, 좌석 사이 통로가 나누는 연속 구간을 추가한다. 출입문 위치가 확인됐다는 이유만으로 보이지 않는 연결이나 통행 가능 구간을 생성하지 않는다. 계단·단차 정보가 없으면 무장애 경로라고 표시하지 않는다.

사용자는 실제로 이용할 출입문을 선택한다. 현재 문 개방 상태를 알려 주는 것처럼 표현하지 않으며, 경로가 확인되지 않는 경우 좌석 위치 안내로 돌아간다. 한쪽 진입만 가능한 줄은 그 조건을 반영한다.

초기 경로 목적은 “목표 좌석까지 다른 좌석 앞을 적게 지나는 경로”다. 양쪽에서 접근 가능한 하나의 연속 구간에 n석이 있고 목표가 왼쪽에서 k번째면 왼쪽의 통과 수는 k-1, 오른쪽은 n-k다. 이 계산은 실제 좌석 순서와 확인된 진입 가능성을 전제로 하며 착석 인원 수를 의미하지 않는다. 통로를 이용하는 경로 중 목표 구간에 진입하도록 하고 다른 좌석줄을 지름길로 통과시키지 않는다.

동률일 때는 확인된 경로의 방향 전환 수 등 명시적인 도면 기준과 고정 순서로 결과를 결정한다. 실제 최단거리, 가장 빠른 문, 혼잡 회피, 충돌 감소 효과는 보장하지 않는다. 미터·도보 시간·실제 최단거리 비교는 검증된 거리 자료가 확보된 뒤 별도 범위로 판단한다. 비상 대피 안내 기능으로 확장하지 않는다.

## 구현 순서와 산출물

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1 | 좌석 자료 전사와 생략·충돌 목록 작성 | 보이는 좌석과 생략 번호를 구분하고 출처·상태를 기록 |
| 2 | 나·다열 1~52번 복원과 데이터 검수 | 번호·줄·좌우 순서·좌표 및 복원 근거를 대조 |
| 3 | SVG 지도와 검색·상태 처리 구현 | 같은 데이터로 지도·줄 상세·텍스트 결과가 일치 |
| 4 | 저장·다국어·접근성 구현 | 저장 실패·버전 변경·언어 변경에도 기본 조회 유지 |
| 5 | 메뉴·대강당 안내·서비스 검색 연동 | 모든 진입 경로와 두 언어에서 동일 기능으로 연결 |
| 6 | 집중 테스트와 브라우저 검증 | 아래 완료 기준을 충족하고 결과를 기록 |
| 7 | 정식 공개 준비 | 검수된 배치 버전과 공개 경로만 연결 |
| 후속 | 출입문·통로 연결과 정적 경로 계산 | 연결 근거를 확보한 구간에 한해 안내 |

화면 구현은 샘플 데이터로 1~2단계와 병행할 수 있다. 샘플과 검수 중 데이터는 공개 결과에 섞지 않는다. 현장 배치가 사진과 같다는 확인을 다시 선행조건으로 요구하지 않는다. 특정 생략 구간이나 통로 연결이 자료로 해결되지 않을 때만 해당 쟁점을 좁혀 확인하거나 미확인 상태로 유지한다.

## 테스트와 공개 완료 기준

### 좌석 데이터 검수

- 전체 좌석 데이터의 고유 ID, 구역·줄 참조, 줄 안 순서 중복, 좌표 범위·중첩을 검사한다.
- 번호 누락은 연속 번호를 강제로 채우는 검사가 아니라, 원본과 별도로 작성한 번호·줄 목록에 대한 차이로 검출한다.
- 사진에 보이는 각 줄의 시작·끝과 좌석 순서를 대조하고, 가려진 번호·생략 번호는 근거와 처리 상태를 기록한다.
- 원본 이미지에서 직접 읽은 사례를 런타임 데이터와 별도로 작성해 `나53 → 05줄`, `나65 → 05줄`, `나66 → 06줄`, `나338 → 26줄`과 같은 경계를 확인한다. 일부 사례 통과로 전수 검수를 대체하지 않는다.
- `나53`과 `다53`이 다른 구역의 좌석으로 조회되는지 확인한다.
- 나·다열 1~52번은 복원 후보와 검수 완료 상태를 구분한다. 13/14, 26/27, 39/40, 52/53 경계를 별도로 확인한다.
- 존재 확인 좌석 수는 검수된 목록에서 산출하며, 기존 문서의 합계와 다르면 차이를 기록한다. 생략·충돌 구간이 남아 있는 부분 목록을 실제 전체 좌석 수로 표시하지 않는다.

| 입력 | 빈값, 구역 미선택, 앞자리 0, 공백, 음수·소수·지수·문자 혼합, 지원 범위 밖 |
| 상태 | 존재 확인·위치 미확인과 존재 불명·없는 번호를 구분하고 임의 좌표를 표시하지 않음 |
| 결과 | 입력 수정·재검색 실패 후 이전 강조가 남지 않음, 전체·줄 상세·텍스트가 같은 좌석을 가리킴 |
| 저장 | 명시적 저장, 교체·삭제, 다른 검색이 저장을 덮어쓰지 않음, 재방문·버전 변경·손상 데이터·저장 제한 |
| 다국어 | 직접 한국어·영어 진입, 언어 전환·새로고침, 원래 구역명·좌석 순서 보존 |
| 검색 연동 | 채플·채플좌석·대강당·좌석·영어 검색, 도서관 좌석 결과 보존, 언어별 링크 |
| 지도·접근성 | 320px·일반 모바일·데스크톱, 브라우저 확대, 키보드·터치, 결과 알림, 선택 표시, 지도 조작 후 복귀 |
| 네트워크 | 페이지 로드 후 좌석 재검색에서 신규 좌석 조회 API나 데이터베이스 요청이 발생하지 않음 |

새 순수 로직·상태·저장 기능에는 해당 실패 위험을 검증하는 집중 테스트를 작성한다. 기존 서비스 검색·내비게이션·사이트맵 테스트를 필요한 범위에서 확장한다. SVG 구현 상세를 그대로 복제한 테스트나 관련 없는 전면 리팩터링은 하지 않는다.

저장소가 지정한 npm으로 `npm run type-check`, 변경 기능의 `npm run test:unit -- <관련 테스트 경로>`, `npm run check:i18n`, `npm run lint`, `npm run build`를 실행한다. PR의 필수 CI는 별도로 완료한다. 계획서 작성 시 수행한 검사는 이 미래 구현 검사를 대신하지 않는다.

브라우저 에뮬레이션과 실제 모바일 기기 확인을 구분한다. 검색부터 강조·저장·재방문까지 확인하고, 측정 없이 “빠르다”거나 특정 지연 수치를 보장하지 않는다. 자동 검사 통과가 스크린리더·현장 좌석 찾기 검증을 대신하지 않는다.

### 정식 MVP 완료 조건

1. 공개하는 모든 정확한 위치에는 번호·줄·순서·좌표 검수 근거가 있다.
2. 사용자 확인으로 존재가 확정된 나·다열 1~52번도 위치 복원 검수를 완료한다. 완료하지 못한 상태는 정식 MVP 완료로 보고하지 않는다.
3. 다른 생략·충돌 번호는 처리 상태를 기록하고, 존재 불명 번호를 없는 좌석으로 단정하지 않는다.
4. 저장 기능과 서비스 검색 등록을 포함한 R01~R11의 초기 적용 부분을 충족한다.
5. 관련 테스트·타입·다국어·lint·빌드와 브라우저 주요 흐름을 통과한다.
6. 실기기·스크린리더·현장 사용성 확인 중 수행하지 못한 항목은 별도로 명시하고 완료로 주장하지 않는다.
7. 검수된 도면 버전으로 메뉴·검색·사이트맵을 연결한다. 구현·데이터가 미완료된 동안 공개 목록에 등록하지 않는다.

위치 미확인 안내는 잘못된 위치를 표시하지 않기 위한 실패 처리이며, 알려진 좌석을 모두 안내한다는 완료 조건을 낮추는 수단으로 사용하지 않는다.
