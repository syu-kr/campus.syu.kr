# 공개 콘텐츠 영어 표시와 자동 번역

기본 UI 사전과 원본 데이터는 분리한다. `/en`에서는 검수한 서비스 공지 영문본과 고정 표시 별칭을 우선하고, 한국어가 남은 허용 공개 필드만 Google Translate로 번역한다. 원본 ID·선택값·검색 조건·검증·저장값은 유지한다. [i18n 정책](I18N_POLICY.md)과 [UI 가이드](UI_DESIGN_GUIDE.md)를 함께 따른다.

## 사용자 흐름과 허용 범위

- English 진입 시 표시된 한국어 공개 문구를 기존 제목·본문·목록 위치에 교체한다. 글별 버튼이나 번역문을 덧붙이는 박스는 사용하지 않는다. 한국어로 돌아가면 원문을 표시한다.
- 페이지 HTML·DOM·입력값을 외부로 보내지 않는다. 브라우저는 공개 출처 ID와 필드명만 보내고 서버가 허용된 원문을 조회한다. 실제 Google 입력은 한글이 있는 공개 문구이며 이미 영어인 문구·순수 숫자는 제외한다.
- 서버는 `announcement`, `competition`, `cafeteria`, `student-restaurant`, `schedule`, `tip`, `service-notice`, `phone`, `shuttle`, `library`, `map`, `course`, `graduation`, `banner`의 허용 공개 필드만 읽는다. 접힌 영역은 실제 렌더링할 때 처리한다.
- 문의·미승인 제안·이메일·룸메이트 글/신고·일정 방/참여자·개인 시간표 이름/메모·졸업 입력/진행·localStorage·공유 토큰·관리자 기록은 제외한다. 교수명·전화번호·좌표·학점·ID도 번역 필드에 넣지 않는다.
- Markdown은 일반 텍스트 노드만 분할하고 링크 주소·코드·문서 구조를 보존한다. 공지 이미지·첨부 PDF·외부 사이트 전체·법률 페이지를 번역하는 기능이 아니다. 합성 공휴일은 UI 영어명을 쓰고 재료·알레르기 정보는 추정하지 않는다.
- 번역문은 `lang="en-x-mtfrom-ko"`, 한국어 원문은 `lang="ko"`로 구분한다. React 텍스트로 교체하고 DOM을 직접 번역하거나 공급자 HTML을 실행하지 않는다. 검색은 한국어 원문을 기준으로 유지한다.
- 페이지에 Google Translate 귀속 배지·링크와 자동 번역 안내를 표시한다. 팝업은 자신의 loading/성공/오류만 표시하며 다른 공지의 실패를 팝업 실패로 안내하지 않는다.

Google Translate가 이 기능의 번역을 제공한다. [Cloud Translation](https://cloud.google.com/translate) · [귀속 요구사항](https://docs.cloud.google.com/translate/attribution) · [배지 출처](../public/brand/google-translate/README.md).

## 검수 서비스 공지

`public/service-notices/en/<slug>.md`는 같은 공지의 영문 표시본이다. 슬러그·날짜·작성자·정렬·페이지 복귀를 유지하며 영어 원문 012는 그대로 사용한다. `sourceSha256`은 원문 전체의 CRLF를 LF로 정규화한 SHA256이다. 원문 변경 후에는 검수 전 영문본을 재사용하지 않고 원문으로 복귀한다. 검토 없이 해시만 갱신하지 않는다. DB 단독 모드에서도 같은 메타데이터·원문 hash 계약을 유지한다. [공지 이전](SERVICE_NOTICE_MIGRATION.md)

## 서버 설정

| 변수 | 용도 |
| --- | --- |
| `GOOGLE_TRANSLATION_API_KEY` | Cloud Translation Basic v2 서버 키. 해당 API로 사용 범위를 제한한다. |
| `FIREBASE_SERVICE_ACCOUNT` | 기존 Firebase Admin 캐시·사용량 저장 권한. 다른 변수 이름과 자동 호환된다고 가정하지 않는다. |
| `RATE_LIMIT_SECRET` | 영속 요청 제한용 HMAC 비밀값. |
| `CONTENT_TRANSLATION_DAILY_CHARACTERS` | UTC 하루 신규 번역 입력 한도. 기본 25,000, 허용 0–1,000,000. |

인증 설정이 모두 있어야 활성화된다. `GET /api/content-translation`의 `available`은 설정 존재 여부이며 공급자 성공 증거가 아니다. 같은 출처의 JSON `POST`만 받고 임의 텍스트·URL·비공개 자료는 거부한다. 미설정이면 원문 조회·Google 호출 전에 503으로 닫는다. API 활성화·키 제한·환경별 프로젝트와 권한은 운영에서 별도로 확인한다. [Google 키 보안](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices)

## 숫자·날짜 검증과 복구

숫자가 있는 문구는 먼저 숫자 값이 보이는 HTML 보호 span과 `translate="no"`, `class="notranslate"`, 요청별 식별자를 사용한다. 공급자 결과의 보호 값·식별자·마크업이 정확히 한 번 남았는지 확인하고, 보호 영역 밖에 원문에 없는 숫자가 생기면 거부한다. raw·한 번 decode한 결과를 각각 검증하며 이중 decode하거나 `dangerouslySetInnerHTML`로 출력하지 않는다.

한국어 달력의 연·월·일은 보호 전에 결합된 표현으로 정리한다. 예를 들어 `2026년 01월 03일`은 `2026/01/03`, `10월 28일~11월 3일`은 `10/28~11/3`으로 값·순서·앞자리 0·범위를 유지한다. 학기·학점·실번호·시간 리터럴은 그대로 둔다. Date 객체로 재계산하거나 날짜를 추정하지 않으며 저장 원문도 바꾸지 않는다.

정상 HTML 응답 중 숫자 복원 검증에 실패한 필드만 불투명 text 토큰으로 한 번 재요청한다. 이미 성공한 필드는 보내지 않는다. 두 호출은 같은 12초 AbortSignal을 공유하며 공급자 HTTP 오류·형식 오류·timeout을 무조건 재시도하지 않는다. fallback에도 같은 숫자/날짜 검증·크기 제한·예산 예약을 적용한다. 실패하면 원문을 제공하고 실패 신규 캐시 lease를 정리한다. 공유 batch의 성공 캐시 저장은 전체 검증이 끝난 뒤 실행한다.

숫자 필드는 별도 처리 버전을 사용하므로 구버전 숫자 캐시·숫자가 든 legacy request cache를 새 결과로 승격하지 않는다. 숫자 없는 유효 캐시의 공유·남은 만료는 유지하고 구버전 문서를 임의로 삭제하지 않는다.

## 캐시·한도

- 클라이언트별 1분 15개 HTTP 요청, 한 요청 최대 12개 공개 출처 묶음, 서버 동시 처리 3개를 유지한다. 입력을 모두 검사한 뒤 처리하며 한 항목의 실패로 다른 출처의 성공을 없애지 않는다. 기존 단건 API도 유지한다.
- 공개 출처 하나는 최대 40필드·원문 6,000 Unicode 문자이며 확장된 공급자 입력은 최대 12,000자다. 브라우저는 분할·중복 병합하고 서버는 응답 형식·크기도 검증한다.
- HTML 보호 태그를 포함한 실제 입력을 매 provider 호출 전에 공유 일일 예산으로 예약한다. fallback도 별도 예약하며 잔여 한도를 넘지 못한다. provider/검증/캐시 저장 실패의 예약도 환불하지 않는다. 원문 길이만으로 비용을 추정하지 않는다.
- 같은 공개 문구·처리 버전·목표 언어는 30일 공유한다. 원문이 바뀌면 별도 항목이며 현재 화면 원문과 응답 원문이 맞을 때만 교체한다. 프로세스 내 요청 병합과 공유 lease로 중복 호출을 제한하되 정확히 한 번의 과금을 보장하지 않는다.
- `public_content_translation_fields`는 문구 캐시, `public_content_translations`는 기존 요청 캐시, `public_content_translation_usage`는 UTC 일별 예약량이다. 유효한 legacy 결과는 남은 만료만 승계하며 브라우저 직접 접근을 열지 않는다.
- 세 collection group의 `expires_at` Timestamp TTL과 추가 만료 지연 0을 확인한다. 앱은 물리 삭제 전에도 만료 캐시를 거부한다. 정책 활성·실제 삭제 시각·청구량은 별도의 운영 증거로 확인한다. [TTL 운영](FIRESTORE_RULES.md)
- 브라우저는 공개 번역을 30분 재사용하고 비활성 항목은 300개 기준으로 정리한다. 언어 전환·페이지 이탈 시 대기 요청을 취소하고 늦은 응답을 이전 화면에 적용하지 않는다. 이미 전송한 요청의 과금 취소는 보장하지 않는다.
- 공급자 성공 뒤 캐시 저장 실패도 원문으로 복귀한다. 이후 Retry의 중복 과금 가능성은 일일 예약 한도 안에서 제한한다. 캐시·예산 저장소를 못 쓰면 신규 번역을 실패로 닫고 내부 오류·키를 사용자에게 노출하지 않는다.

## 실패 안내와 운영 확인

설정 누락·연결 실패·한도·검증 거부에는 원문과 해당 언어 속성을 유지하고 페이지 공통 영역에서 안내한다. 원문이 바뀌면 페이지를 다시 열도록 안내한다. 팝업 Retry는 같은 source kind/id/category의 실패만, 페이지 Retry는 활성 실패를 재시도하며 지속 상태 문단으로 초점을 이동한다. 닫기·Escape·초점 제한과 언어 전환 후 늦은 응답 무시는 유지한다.

모의 회귀는 기존 위치 교체·원문 복귀·캐시 재사용·보호 숫자 거부·fallback·저장소 실패·개인 입력 제외를 확인한다. 실제 공개 문구의 소량 번역 성공·반복 요청의 추가 예약 0·오류 후 복구는 별도로 확인하며 과거 테스트 수나 `available:true`로 대신하지 않는다. 한도를 소진하거나 일반 사용자 입력을 보내 시험하지 않는다.

학사 용어·지원 조건·긴 본문 품질, 실제 청구·예산 알림·quota·TTL 물리 삭제는 운영 확인 대상이다. Google 일일 quota의 Pacific Time 초기화와 앱 UTC 예산은 다르며 예산 알림은 자동 과금 차단이 아니다. 브라우저 번역 교체는 초기 HTML·OG·검색 스니펫의 영어 출력을 보장하지 않으므로 서버 metadata·canonical·hreflang·본문 언어를 따로 검사한다. 데이터 연결 전환은 [전환 절차](FIREBASE_CUTOVER.md)를 따른다.
