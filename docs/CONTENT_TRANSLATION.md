# 공개 콘텐츠 영어 표시와 자동 번역

기본 UI 사전과 원본 데이터는 분리한다. `/en`에서는 검수한 서비스 공지 영문본과 고정 표시 별칭을 우선하고, 한국어가 남은 허용 공개 필드는 Google Translate로 자동 번역한다. 원본 ID·선택값·검색 조건·검증·저장값은 유지한다. [i18n 정책](I18N_POLICY.md)과 [UI 가이드](UI_DESIGN_GUIDE.md)를 함께 따른다.

## 사용자 흐름

- English 화면에 들어오면 표시된 한국어 공개 필드를 자동으로 번역해 기존 제목·본문·목록 위치에 교체한다. 글별 버튼과 번역문을 덧붙이는 별도 박스는 사용하지 않는다. 한국어 화면으로 전환하면 원문을 표시한다.
- 페이지 전체 HTML·DOM·입력값을 외부로 보내지 않는다. 브라우저는 공개 출처 ID와 필드명만 서버에 보내고 서버가 허용된 원문을 조회한다. 실제 Google 요청에는 한글이 포함된 공개 문구만 들어간다. 이미 영어인 문구·순수 숫자는 요청하지 않는다.
- 설정 누락·연결 실패·번역 한도·잘못된 응답에는 원문을 유지하고 페이지 공통 영역에서 안내·복구한다. 원문이 바뀌면 페이지를 다시 열도록 안내한다. Markdown은 일반 텍스트 노드만 고정 분할하며 링크 주소·코드·원래 문서 구조를 유지한다.
- 페이지 공통 영역에 Google Translate 귀속 배지·링크와 자동 번역 안내를 표시한다. 번역은 `lang="en-x-mtfrom-ko"`, 한국어 원문은 `lang="ko"`로 구분한다. React 렌더링으로 교체하며 브라우저 번역처럼 DOM을 직접 변경하지 않는다.
- 기존 검색은 한국어 원문을 기준으로 동작한다. 기계 번역 결과를 기존 검색 색인이나 선택값으로 사용하지 않는다.

Google Translate가 이 기능의 번역을 제공한다. [Cloud Translation](https://cloud.google.com/translate) · [귀속 요구사항](https://docs.cloud.google.com/translate/attribution) · [공식 배지 출처](../public/brand/google-translate/README.md).

## 허용 범위

서버는 `announcement`, `competition`, `cafeteria`, `student-restaurant`, `schedule`, `tip`, `service-notice`, `phone`, `shuttle`, `library`, `map`, `course`, `graduation`, `banner`의 공개 ID와 허용 필드만 직접 조회한다. 식사·일정·강의·층 등 필요한 공개 단위로 등록하며 접힌 영역은 실제로 렌더링할 때 처리한다.

문의·미승인 제안, 이메일, 룸메이트 글·신고, 일정 방·참여자, 개인 시간표 이름·메모, 졸업 입력값·진행 상황, localStorage, 공유 토큰과 관리자 기록은 제외한다. 교수 이름, 전화번호·좌표·학점·ID도 번역 필드에 포함하지 않는다. 합성 공휴일은 기존 UI 영어명을 사용하며, 만나의집 재료·알레르기 정보는 추정하지 않는다. 공지 이미지·첨부 PDF·외부 사이트 전체나 기존 법률 페이지를 번역하는 기능은 아니다.

## 검수 서비스 공지

`public/service-notices/en/<slug>.md`는 기존 공지의 영문 표시본이다. 새 공지로 계산하지 않으므로 슬러그·날짜·작성자·정렬·페이지 복귀는 같다. 영어 원문 012는 그대로 사용한다.

영문본의 `sourceSha256`은 원문 전체 CRLF를 LF로 정규화한 SHA256이다. 원문이 바뀌면 검수 전 영문본을 재사용하지 않고 한국어 원문으로 복귀한다. 내용 검토 없이 해시만 갱신하지 않는다. 과거 공지의 날짜와 당시 설명을 현재 기능으로 임의 수정하지 않는다.

## 서버 설정

| 변수 | 용도 |
| --- | --- |
| `GOOGLE_TRANSLATION_API_KEY` | Cloud Translation Basic v2 서버 키. 해당 API로 사용 범위를 제한한다. |
| `FIREBASE_SERVICE_ACCOUNT` | 기존 Firebase Admin 공유 캐시·사용량 저장 권한. 다른 환경변수 이름이 자동 호환된다고 가정하지 않는다. |
| `RATE_LIMIT_SECRET` | 기존 영속 요청 제한용 HMAC 비밀값. |
| `CONTENT_TRANSLATION_DAILY_CHARACTERS` | UTC 하루 신규 번역 입력 한도. 기본 25,000, 허용 0–1,000,000. |

앞의 인증 설정이 모두 있어야 활성화된다. `GET /api/content-translation`은 비밀값 없이 `available`만 반환한다. `POST`는 같은 출처의 JSON 요청만 받으며 임의 텍스트·URL·비공개 자료를 받지 않는다. 미설정이면 원문 조회나 Google 호출 전에 503을 반환한다.

운영자는 API 활성화, 키 제한, Google 과금·할당량·예산 알림, Firebase 권한을 확인한다. 사용자가 등록한 로컬 인증 설정으로 2026-10-26 실제 공개 제목 번역·캐시 재사용을 확인했다. 설정 존재 여부만 반환하는 GET의 `available:true`를 공급자 성공 증거로 사용하지 않는다. [Google 키 보안](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices).

## 캐시·한도·복구

- 클라이언트별 1분 15개 HTTP 요청 제한을 유지한다. 한 HTTP 요청은 최대 12개 공개 출처 요청을 묶고 서버 동시 처리는 3개로 제한한다. 모든 입력을 먼저 검사한 뒤 처리하며 일부 실패가 다른 항목의 성공을 없애지 않는다. 기존 단건 API도 유지한다.
- 공개 출처 요청 하나는 최대 40필드·원문 6,000 Unicode 문자다. 브라우저는 이를 자동 분할하고 중복 요청을 합친다. 숫자 보호 뒤의 실제 공급자 입력량을 공유 일일 예산에 예약한다. 실패한 예약은 돌려주지 않는다. 한도에 도달하면 남은 자동 요청도 중단한다.
- 숫자·날짜·시간 토큰을 보호·복원하고 누락·변조·추가 응답을 거부한다. 번역 의미의 정확성을 보증하는 검사는 아니므로 학사 용어 품질 검토가 별도로 필요하다.
- 캐시는 정확히 같은 공개 문구·처리 버전·목표 언어를 기준으로 30일 공유한다. 같은 문구가 다른 페이지·필드·출처에 있어도 재사용한다. 원문이 달라지면 별도 항목이 되며, 응답의 원문과 현재 화면의 원문이 일치할 때만 교체한다. 같은 프로세스의 요청과 공유 캐시 lease로 중복 공급자 호출을 제한한다.
- Firestore `public_content_translation_fields`는 문구별 30일 캐시다. 기존 `public_content_translations`의 유효한 결과는 남은 만료 기간을 유지하며 승계한다. `public_content_translation_usage`는 UTC 일별 예약량이다. 브라우저 직접 접근을 열지 않는다.
- 세 collection group의 `expires_at` Timestamp에 TTL 정책을 설정하고 추가 만료 지연은 0으로 유지한다. 앱이 만료 시각을 직접 검사하므로 TTL 삭제 전에도 만료 번역을 재사용하지 않는다. 사용자 승인 후 콘솔에서 세 정책을 생성했으며 2026-10-27 12:50:36 KST 실제 GET에서 모두 `ACTIVE`·추가 지연 0초를 확인했다. 실제 물리 삭제·청구량은 별도 확인 대상이다. 근거와 과거 403 기록은 [Firebase 실행 기록](FIREBASE_MIGRATION_IMPLEMENTATION_2026-10-26.md)에 기록한다.
- 브라우저 메모리는 최근 공개 번역을 30분 재사용하며 비활성 항목은 300개 기준으로 정리한다. 한국어 전환·페이지 이탈 전에 대기 중인 요청은 취소하고 이미 시작한 응답은 이전 화면에 반영하지 않는다. 이미 공급자로 전송한 요청의 과금 취소를 보장하지 않는다.
- 공급자 성공 뒤 캐시 저장이 실패하면 원문으로 복귀한다. 이후 재시도에 중복 과금 가능성이 있으며 일일 예약 한도 내에서 제한한다. 외부 과금이 정확히 한 번만 발생한다고 보장하지 않는다.
- 캐시나 예산 저장소를 사용할 수 없으면 새 번역은 실패로 닫는다. 공급자·인증·SDK 오류를 사용자에게 노출하지 않는다.

## 확인 경계

테스트는 모의 응답으로 자동 실행·기존 위치 교체·원문 복귀·재사용·원문 변경·늦은 응답·잘못된 응답·한도·저장소 실패를 확인한다. 2026-10-26 실제 검증은 다음과 같다.

- 공개 제목 한 건: 200 응답과 신규 입력 9자 예약, 동일 요청 반복은 추가 예약 0자.
- 숫자 포함 제목·서로 다른 글의 동일 문구를 묶은 새 API: 모두 200, 숫자 보존·공유 문구 결과 일치, 신규 예약 52자, 순서를 바꾼 반복 요청은 추가 예약 0자.
- 실제 언어 선택: 한국어 → Global (English) → 한국어 → English 통과. 꿀팁 12개 출처의 78개 표시 노드가 기존 위치에서 교체됐고 최초 신규 예약은 770자였다. 이후 새 브라우저와 재진입에서 캐시를 재사용했다. 1440·390px 가로 넘침·브라우저 오류가 없었다.

위 숫자는 앱 캐시·사용량의 증거이며 Google 청구서 대조나 모든 학사 용어의 번역 품질 검토는 아니다. 원본 공지·배너·문의는 변경하지 않았다.

## 자동 전환 최종 회귀 확인 — 2026-10-26

- 전체 단위 테스트 211개 파일·1,875개 테스트, 전체 ESLint, 타입 검사, i18n 검사, unused 검사, 최종 프로덕션 빌드가 통과했다.
- 기존 37개 경로 × 한국어/영어 × 1440/390px 총 148개 화면을 검사했다. 모의 공개 번역 655건에서 출처·필드 불일치가 없었으며, 실제 Google 호출과 업무 변경 요청은 차단했다.
- 별도의 한국어 잔존 검사로 공휴일명·학기/날짜·도서관 중복 원문을 발견해 고정 영문 표시로 정리했다. 수정한 세 경로의 12개 화면을 재검사해 잔존 문구·소스 실패·가로 넘침·브라우저 오류가 없었다. 공휴일 원문 검색, 학기 원본 값, 좌석 번호·연결은 유지했다.
- 고의 503 실패 4개 화면에서 원문과 한국어 언어 속성·페이지 공통 재시도를 확인했다. 연락 양식의 개인 입력과 임의 DOM 텍스트를 번역에 보내지 않으며, 요청에 공개 출처·필드명 이외의 페이지 본문이 포함되지 않는 것도 확인했다.
- 긴 모바일 페이지의 언어 복귀 검사에서는 자동 스크롤 중 팝업을 여는 테스트 타이밍을 확인했다. 버튼을 화면 중앙으로 스크롤한 후 일반 클릭으로 원문 복귀와 재번역 캐시 흐름이 통과했다. 강제 클릭이나 제품 Select 동작 변경은 하지 않았다.
- 이전 전체 검사에서 동시 빌드로 일부 테스트가 시간 초과된 뒤 빌드와 겹치지 않게 2 worker로 전체 재실행해 통과했다. SSR 테스트는 실제 영문 Locale Provider를 반영하고 초기 원문 제목·본문·schema 보존을 검증했다.

로컬 근거는 무시되는 `output/playwright/admin-dashboard/`의 `real-translation.json`, `real-auto-translation.json`, `live-english-page.json`, `auto-translation-final.json`, `auto-translation-metadata.json`과 검사 로그에 둔다. 넓은 투어의 최초 잔존 결과도 덮어쓰지 않고 보존한다. 검증 당시 셔틀 등 외부 공급자의 기존 장애까지 해결했다고 해석하지 않는다. 실제 운영 배포·콘텐츠 데이터 마이그레이션·Git 병합은 실행하지 않았다.

활성화 전 공지 지원 조건, 학사 용어, 메뉴명, 강의실명과 긴 본문을 표본 검토한다. 브라우저에서 교체하는 번역을 초기 HTML·메타데이터의 영문 SEO 개선으로 계산하지 않는다. 검수된 서버 출력은 canonical·hreflang·메타데이터·본문 언어를 별도로 확인한다. 자동 번역은 수동 버튼 방식보다 신규 요청이 늘 수 있으며 중복 제거가 무과금을 보장하지는 않는다.


## Firebase 이전 후속 검증 — 2026-10-27

10월 27일 후속 검사와 Production 키 등록·실제 데이터 최신성·최종 후보의 남은 게이트는 [배포 전 진행 상태](PRE_RELEASE_PROGRESS_2026-10-27.md)를 따른다. 아래 148뷰와 과거 전체 성공 수치는 각 실행 당시의 근거이며 새 후보의 전체 CI 통과를 뜻하지 않는다.

서비스 공지 19개·검수 영문 18개와 공개 자료 23개는 실제 Firebase로 복사·검증했다. 이전 절의 미이전 기록은 그 당시 상태이며 최신 결과는 [실행 기록](FIREBASE_MIGRATION_IMPLEMENTATION_2026-10-26.md)을 따른다. 최종 148뷰의 공개 텍스트 등록·교체·실패/재시도·언어 왕복·개인 입력 제외는 mock provider로 검증해 자연스러운 번역 품질이나 실제 Google 속도라고 계산하지 않았다.

영어 홈의 늦은 안내 삽입 CLS, 클라이언트 이동 후 여백, 재시도 초점 유실과 확대된 영어 단어 넘침을 보완했다. 02:06 KST까지 미설정이던 TTL 세 정책은 사용자 승인 후 콘솔에서 생성했고, 12:50:36 KST GET에서 모두 `ACTIVE`·추가 지연 0초를 확인했다. 같은 프로젝트의 Google 일반 모델 일일 문자 한도는 무제한에서 50,000자로 변경해 콘솔 성공 안내와 적용값을 확인했다. 앱의 25,000자/UTC 예산은 유지하며 Google의 태평양 시간 기준 일일 한도와 구분한다. 서버 계정의 quota 조회 403은 남아 있고 실제 한도 소진·TTL 물리 삭제·예산 알림·과금은 미검증이다. 새 IAM 부여·운영 앱 배포·병합은 수행하지 않았다. 후속으로 사용자의 ‘Production 번역 키만 등록 승인’을 받아 Vercel `syu-campus`의 Production에 `GOOGLE_TRANSLATION_API_KEY` 한 개를 Secret으로 저장하고 새로고침 후 등록 행을 확인했다. 값은 대화·로그에 출력하지 않았다. 재배포·backend/source 전환은 하지 않았으며, 배포된 앱의 설정 반영·키 유효성·실제 번역 성공은 아직 검증하지 않았다.
