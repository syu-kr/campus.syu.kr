# 관측으로 보정하는 도착예상 · 2026-11-02

사용자 결정에 따라 독립 실측 승인 대기를 없애고 학습 중인 예상 시간을 제공한다. `FIELD_PILOT.md`의 독립 검증 공개 게이트는 이전 실험 기록이며 현재 노출 조건이 아니다. 오차·가용률은 개선 지표로 계속 확인한다. 예측을 이미 검증된 실측이라고 표시하지 않는다.

## 계산과 업데이트

- `/preview/locations` 조회는 신뢰된 서버 수신 자료만 저장하고 같은 수신시각은 한 번만 저장한다. 좌표·회차를 클라이언트가 제출할 수 없다. 현장 확인 사건 POST는 계속 관리자 인증이 필요하다.
- 브라우저는 각 요청 완료 후 5~10초 간격을 무작위 선택한다. 화면의 초시계 재렌더로 간격을 다시 정하지 않는다. 원천 캐시는 5초이고 동시 요청은 합친다. 페이지가 열려 있는 동안 수집하며 상시 백그라운드 수집기는 아니다.
- 수신 관측·회차·사건 후보·진행 상태와 `shuttle_eta/current`를 같은 트랜잭션에서 갱신한다. 차량 커서는 현재 문서에 함께 보관하며 레거시 커서는 첫 접근에서 이전한다. 일반 수집은 5초 구간당 한 프레임으로 합치고, 연속된 빈 상태의 추가 쓰기를 생략한다. 늦은 요청이 최신 상태를 되돌리지 않는다. 운휴·주말·불확실한 달력·오래된 위치는 조회/저장과 예측에서 제외한다.
- 등록 좌표와의 실제 관측 차이(학교 최대 153m, 현장 도착 출구 106m)를 반영해 학교는 180m, 그 외는 125m 안을 도착 후보로 기록하고 이탈은 각각 50m 넓게 잡는다. 후보 사건과 시간 범위는 유지하며 실제 승하차 확정으로 취급하지 않는다. 같은 회차의 현장 기록과 계속 대조해 보정한다.
- 지도와 같은 방향별 도로선에 투영한다. 노선 상태와 반대 방향, 도로에서 200m 넘게 떨어진 위치, 큰 역주행은 보류한다. 회송 화랑대 학교→역은 여객 ETA로 사용하지 않는다.
- 구간별 기본값은 누적 이력과 새 출발→도착 관측이다. 표본이 없는 구간은 2026-10-31 보관한 OSRM 도로 소요시간을 초기 참고값으로 사용한다. 예시 운행 타이밍은 사용하지 않는다.
- 한국시각 요일×30분×시간표 유형의 셀을 기본값과 완만하게 섞는다(`n/(n+5)`). 셀이 적다는 이유로 예측 전체를 막지 않는다. 새 완결 관측은 기존 값 80%+새 값 20%로 갱신한다. 현재 차량의 위치 진행에서 구한 이동 페이스도 남은 시간에 반영한다.
- 출발 시간표는 기점에 정지한 차량의 출발 대기로 반영한다. 배차 간격을 주행시간으로 취급하지 않는다. 중간 정차는 관측한 정차시간을 쓰고 없으면 초기 추정 30초를 쓴다.
- 프리뷰에서 시간표와 정류장 안내를 함께 표시한다. 기점은 다음 시간표 출발 시각을 그대로 사용한다. 별도의 `scheduledArrivals`는 시간표 출발+시간대별 구간 통계로 계산하며, 최신 위치를 쓰는 `arrivals`와 구분한다. 위치가 없거나 지연되어도 시간표 기준 추정은 그 기준을 표시하여 제공한다. 통과한 정류장은 후속 출발편으로 넘어가며, 후속편이 없으면 막차 통과를 표시한다. 실제 통과를 확인하지 못한 종료 추정에는 시간표 기준을 붙인다.
- 최신 위치를 기준으로 최대 20분 앞의 도착을 계산한다. 90초가 지난 위치·지난 예측은 숫자를 지운다. 장치 측정시각이 없으면 수신 관측 기준임을 `measurementSource:receiver`로 유지한다.
- 응답 `status:learning`과 보정 중 안내를 표시한다. `basis:history/observed/route`로 출처를 구분한다. 차량 선택 조회는 해당 차량만 계산하며 사설 식별자·좌표는 ETA 응답에 포함하지 않는다.

## 30일 이력의 일회 이관

```powershell
npm run import:shuttle-history -- C:/private/history.json
npm run import:shuttle-history -- C:/private/history.json --receipts=C:/private/receipts.json
npm run import:shuttle-history -- C:/private/history.json --receipts=C:/private/receipts.json --apply
```

기본값은 읽기 전용 dry-run이다. 입력의 모든 정류장 감지를 `shuttle_history_imports/{sha256}`에 비식별 이관한다. 같은 원본 차량 별칭·같은 날짜에서 연속된 석계→태릉입구 감지만 구간 초기값으로 연결한다. 다른 차량 별칭을 합치거나 역→학교 시간을 임의로 만들어내지 않는다. 분 단위 감지 차이는 실제 출발·도착 정답이 아닌 초기 추정 자료다.

이관 시 보관 중인 v2 사건도 시간순으로 재생해 초기 통계에 반영하고, 이력·새 관측 요약을 `shuttle_eta/history`에 저장한다. 원본 SHA로 재실행을 중복 방지한다. 현재의 라이브 모델과 좌표 상태는 덮어쓰지 않는다. 실제 데이터·URL·인증값은 공개 저장소에 넣지 않는다.

기본 드라이런은 로컬 입력만 사용하며 Firestore에 접속하지 않는다. 위의 receipts 파일은 비공개 원시 프레임 배열이다. 원격 읽기가 필요한 경우에만 `--read-receipts`를 명시한다. `--apply`는 로컬 receipts 또는 명시적인 원격 읽기 옵션을 요구한다.

## 반복 조회와 계측

현재 상태는 5초, 과거 프로필은 버전별로 캐시한다. 차량 선택도 같은 스냅샷에서 계산하며 현재 상태에 프로필이 있으면 영구 모델을 다시 읽지 않는다. 운행 창 밖에서는 위치·ETA 자동 폴링과 관리자 자동 수집이 멈추고, 시간표 결과는 최초 조회·화면 복귀 시 재사용한다. 관리자는 현장 기록 도구를 켠 뒤 확인한 도착·출발·통과만 제출한다.

`FIRESTORE_USAGE_LOGS=1`을 설정하면 서버 프로세스별 읽기·쓰기·쿼리 반환 문서 수·캐시·트랜잭션 시도를 1분 단위로 합산해 기존 로그에 출력한다. 사용자·차량 식별자와 좌표는 기록하지 않는다. 프로세스 종료 전까지 비어 있는 로그 구간은 Cloud Monitoring으로 함께 확인한다. 로그 카운터는 실제 청구서와 분리한다.

## 회차별 ETA 평가

`npm run evaluate:shuttle-eta -- C:/private/forecast-snapshot.json`은 운영 데이터베이스에 접속하지 않고 정류장·요일·30분 시간대·측정 방식별 오차, 이른 안내 비율, 표출률을 계산한다. 입력은 `forecasts`와 `arrivals` 배열이며 route, 비공개 runId, 방향별 visitId로 연결한다. forecasts에는 발행 시각 issuedAt과 실제 표출 arrivalAt, 같은 시점의 baselineArrivalAt을 밀리초 epoch으로 넣는다. 미표출은 null이다. 선택 학습 시각 modelTrainedThrough/baselineTrainedThrough는 issuedAt 이하여야 한다. arrivals에는 실제 도착 observedAt과 method(receiver/source/field)를 넣는다. 위치 수신이나 출발·통과를 도착 정답으로 넣지 않는다.

같은 발행 기회에 모델과 기준선이 모두 제공된 경우에만 오차를 비교한다. 중복 발행·다중 정답·발행 전 도착·2시간 또는 한국 운행일을 넘긴 연결을 제외한다. 회차 식별자는 집계 결과에 포함하지 않는다. 기존 감지 이력에는 과거 발행 응답이 없으므로 실제 운행 오차는 별도의 비공개 발행·도착 스냅샷을 수집한 뒤 평가한다.

## 보관 크기와 버킷 전환 계획

- 원시 수신·현장 기록·이관 이벤트는 30일 TTL과 일일 정리를 적용한다. 기기/차량 원본 ID나 승객 정보는 저장하지 않는다.
- 최신 상태는 최대 10대, 미완결 사건/중복방지 키는 최근 2시간·128개씩이다. 구간별 계산 통계는 최근 시간 셀 64개로 제한한다. 장기 통계는 좌표·차량·회차 ID가 없는 `shuttle_eta/model`에 따로 유지하여 원자료 만료 후에도 이어서 학습한다. 전체 원자료를 예측 요청마다 읽지 않는다.
- 단일 수집 흐름에서 7.5초 평균·하루 10시간이면 약 4,800프레임/일, 30일 약 144,000프레임이다. 실제 양은 서버 인스턴스·관측 차량 수에 따라 달라지므로 보관 문서 수와 평균 바이트를 함께 계측한다.
- **보관 100,000프레임 또는 원자료 500MB**를 전환 검토선으로 둔다. 그때 최근 7일과 최신 통계만 Firestore에 두고 나머지를 비공개 Storage의 일자별 gzip NDJSON으로 분리한다. 버킷 원자료도 총 30일 보관을 유지한다.
- 버킷 전환은 이번 변경에서 실행하지 않는다. 도입 시 dry-run, 객체 체크섬·건수 검증, 재시도 중복 방지, 이관 후 읽기 검증을 마친 뒤에만 원본 삭제를 허용한다. 누적량만 보고 검증 없이 문서를 지우지 않는다.

## 표시

운행 전·운행 중·운행 종료를 사용한다. 방학 표는 화랑대만 제공한다. 온라인 주간에는 별내도 온라인 탭을 현재로 표시하고, 출발 시각은 기존 학기 시간표와 같다는 안내를 유지한다.

노선 배지는 별도 달력·위치 수신 대기 상태를 사용하지 않는다. 기존 공휴일 JSON과 등록된 운휴일에 운행 종료를 표시하고, 나머지는 적용 시간표의 첫 출발 전·첫 출발부터 막차 출발까지·막차 출발 이후로 구분한다. 위치가 남아 있어도 막차 출발 이후 배지를 운행 중으로 연장하지 않는다. 달력 자료가 오래된 경우에도 시간표 배지를 확인 중으로 바꾸지 않으며, 실제 수집·위치 기반 ETA의 달력 안전 조건은 별도로 유지한다.

시간표는 데스크톱에서 왼쪽, 도착예상은 오른쪽에 표시하고 모바일에서는 접기 없이 세로로 배치한다. 시간표 종류는 실제 탭 수만큼 같은 너비로 채운다. 정류장 연결선의 아래 방향 화살표와 도로에 투영한 최신 차량 위치로 운행 흐름을 표시한다. 대중교통의 새 부분 응답은 `partial`로 안내하고, 전체 조회 실패로 보존한 과거 응답만 `stale`로 표시한다. 정상 조회에서 도착 버스 수가 감소한 경우 이전 예측을 보존하지 않는다.
