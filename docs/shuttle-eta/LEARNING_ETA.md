# 관측으로 보정하는 도착예상 · 2026-11-02

사용자 결정에 따라 독립 실측 승인 대기를 없애고 학습 중인 예상 시간을 제공한다. `FIELD_PILOT.md`의 독립 검증 공개 게이트는 이전 실험 기록이며 현재 노출 조건이 아니다. 오차·가용률은 개선 지표로 계속 확인한다. 예측을 이미 검증된 실측이라고 표시하지 않는다.

## 계산과 업데이트

- `/preview/locations` 조회는 신뢰된 서버 수신 자료만 저장하고 같은 수신시각은 한 번만 저장한다. 좌표·회차를 클라이언트가 제출할 수 없다. 현장 확인 사건 POST는 계속 관리자 인증이 필요하다.
- 브라우저는 각 요청 완료 후 5~10초 간격을 무작위 선택한다. 화면의 초시계 재렌더로 간격을 다시 정하지 않는다. 원천 캐시는 5초이고 동시 요청은 합친다. 페이지가 열려 있는 동안 수집하며 상시 백그라운드 수집기는 아니다.
- 수신 관측·회차·사건 후보·진행 상태와 `shuttle_eta/current`를 같은 트랜잭션에서 갱신한다. 늦은 요청이 최신 상태를 되돌리지 않는다. 운휴·주말·불확실한 달력·오래된 위치는 조회/저장과 예측에서 제외한다.
- 등록 좌표와의 실제 관측 차이(학교 최대 153m, 현장 도착 출구 106m)를 반영해 학교는 180m, 그 외는 125m 안을 도착 후보로 기록하고 이탈은 각각 50m 넓게 잡는다. 후보 사건과 시간 범위는 유지하며 실제 승하차 확정으로 취급하지 않는다. 같은 회차의 현장 기록과 계속 대조해 보정한다.
- 지도와 같은 방향별 도로선에 투영한다. 노선 상태와 반대 방향, 도로에서 200m 넘게 떨어진 위치, 큰 역주행은 보류한다. 회송 화랑대 학교→역은 여객 ETA로 사용하지 않는다.
- 구간별 기본값은 제공받은 이력과 새 출발→도착 관측이다. 표본이 없는 구간은 2026-10-31 보관한 OSRM 도로 소요시간을 초기 참고값으로 사용한다. 예시 운행 타이밍은 사용하지 않는다.
- 한국시각 요일×30분×시간표 유형의 셀을 기본값과 완만하게 섞는다(`n/(n+5)`). 셀이 적다는 이유로 예측 전체를 막지 않는다. 새 완결 관측은 기존 값 80%+새 값 20%로 갱신한다. 현재 차량의 위치 진행에서 구한 이동 페이스도 남은 시간에 반영한다.
- 출발 시간표는 기점에 정지한 차량의 출발 대기로 반영한다. 배차 간격을 주행시간으로 취급하지 않는다. 중간 정차는 관측한 정차시간을 쓰고 없으면 초기 추정 30초를 쓴다.
- 최신 위치를 기준으로 최대 20분 앞의 도착을 계산한다. 90초가 지난 위치·지난 예측은 숫자를 지운다. 장치 측정시각이 없으면 수신 관측 기준임을 `measurementSource:receiver`로 유지한다.
- 응답 `status:learning`과 보정 중 안내를 표시한다. `basis:history/observed/route`로 출처를 구분한다. 차량 선택 조회는 해당 차량만 계산하며 사설 식별자·좌표는 ETA 응답에 포함하지 않는다.

## 30일 이력의 일회 이관

```powershell
npm run import:shuttle-history -- C:/private/history.json
npm run import:shuttle-history -- C:/private/history.json --apply
```

기본값은 읽기 전용 dry-run이다. 입력의 모든 정류장 감지를 `shuttle_history_imports/{sha256}`에 비식별 이관한다. 같은 원본 차량 별칭·같은 날짜에서 연속된 석계→태릉입구 감지만 구간 초기값으로 연결한다. 다른 차량 별칭을 합치거나 역→학교 시간을 임의로 만들어내지 않는다. 분 단위 감지 차이는 실제 출발·도착 정답이 아닌 초기 추정 자료다.

이관 시 보관 중인 v2 사건도 시간순으로 재생해 초기 통계에 반영하고, 이력·새 관측 요약을 `shuttle_eta/history`에 저장한다. 원본 SHA로 재실행을 중복 방지한다. 현재의 라이브 모델과 좌표 상태는 덮어쓰지 않는다. 실제 데이터·URL·인증값은 공개 저장소에 넣지 않는다.

## 보관 크기와 버킷 전환 계획

- 원시 수신·현장 기록·이관 이벤트는 30일 TTL과 일일 정리를 적용한다. 기기/차량 원본 ID나 승객 정보는 저장하지 않는다.
- 최신 상태는 최대 10대, 미완결 사건/중복방지 키는 최근 2시간·128개씩이다. 구간별 계산 통계는 최근 시간 셀 64개로 제한한다. 장기 통계는 좌표·차량·회차 ID가 없는 `shuttle_eta/model`에 따로 유지하여 원자료 만료 후에도 이어서 학습한다. 전체 원자료를 예측 요청마다 읽지 않는다.
- 단일 수집 흐름에서 7.5초 평균·하루 10시간이면 약 4,800프레임/일, 30일 약 144,000프레임이다. 실제 양은 서버 인스턴스·관측 차량 수에 따라 달라지므로 보관 문서 수와 평균 바이트를 함께 계측한다.
- **보관 100,000프레임 또는 원자료 500MB**를 전환 검토선으로 둔다. 그때 최근 7일과 최신 통계만 Firestore에 두고 나머지를 비공개 Storage의 일자별 gzip NDJSON으로 분리한다. 버킷 원자료도 총 30일 보관을 유지한다.
- 버킷 전환은 이번 변경에서 실행하지 않는다. 도입 시 dry-run, 객체 체크섬·건수 검증, 재시도 중복 방지, 이관 후 읽기 검증을 마친 뒤에만 원본 삭제를 허용한다. 누적량만 보고 검증 없이 문서를 지우지 않는다.

## 표시

운행 전·운행 중·운행 종료를 사용한다. 방학 표는 화랑대만 제공한다. 온라인 주간에는 별내도 온라인 탭을 현재로 표시하고, 출발 시각은 기존 학기 시간표와 같다는 안내를 유지한다.
