# English 공지 번역 오류 보완 — 2026-10-27

숫자·날짜 검증을 유지하면서 실제 실패 공지의 제목·AI 요약·기한 번역을 보완했다. 수정 코드로 실제 Google 응답을 받아 세 필드가 성공하는 것을 로컬에서 확인했다. **이 결과는 새 코드의 프로덕션 배포 완료를 의미하지 않는다.** 최종 CI·squash merge·운영 source SHA와 운영 UI 재검증은 아래 출시 확인란에 이어 기록한다.

## 문제와 사용자 영향

운영 학사공지 `academic-7e020dc6aba3`의 `title`, `aiSummary.summary`, `aiSummary.deadline` 번역이 개별 요청에서 `503 TRANSLATION_FAILED`를 반환했다. 원문은 계속 표시됐지만 English 홈의 해당 공지가 한국어로 남았다.

최초 진단에서는 실제 Google 응답이 200이고 보호 토큰도 남았지만, 제목에 원문에 없는 `1st`가 추가됐다. 서버의 새 숫자 추가 금지 검사가 이를 거부했다. 오류를 없애기 위해 이 검사를 해제하지 않았다. 요약·기한의 모든 최초 실패 원인이 제목과 같았다고 단정하지 않는다.

페이지 전체의 번역 상태를 팝업에도 사용하던 문제도 있었다. 팝업 제목·설명이 성공했어도 다른 공지의 실패가 팝업의 오류/Retry처럼 보였다.

## 숫자·날짜 처리

첫 시도는 숫자 값이 보이는 HTML 보호 span으로 감싼다. Google에는 `format: html`로 보내고 `translate="no"`, `class="notranslate"`, 요청마다 다른 식별자를 함께 사용한다. 숫자의 문맥이 보이도록 하되 공급자 응답을 신뢰하지 않고 복원 단계에서 검증한다. HTML 응답의 검증이 거부된 숫자 필드만 불투명 토큰의 `format: text` 방식으로 한 번 더 시도한다.

- HTML 보호 span과 text 보호 토큰은 반환 응답에 정확히 한 번 있어야 한다. HTML 경로는 값·식별자·마크업을, text 경로는 식별자를 그대로 대조한다. 누락·변형·중복은 검증을 통과하지 못한다.
- 어느 경로든 보호 부분 밖에 원문에 없는 숫자가 추가되면 실패한다. 숫자 HTML entity로 새 숫자를 넣은 응답도 검사한다. fallback에서도 같은 날짜 정규화와 숫자·날짜 보존 검증을 통과해야 한다.
- HTML 요청은 원문 특수문자를 먼저 escape하고, 공급자가 새 마크업을 추가한 HTML 응답을 거부한다. 두 방식 모두 보호 부분을 복원한 최종 문자열을 기존 React 텍스트 위치에 표시하며 HTML로 실행하지 않는다.
- raw 응답과 한 번 decode한 응답에서 보호 token의 정확한 1회를 각각 확인한다. decoded 응답의 보호 token 밖 숫자를 검사한 뒤 원래 숫자를 복원하며 추가 decode하지 않는다. 원문에 있던 `<script>`, `&#52;` 같은 문자열을 공급자 마크업이나 새 숫자로 이중 해석하지 않는다. 결과를 `dangerouslySetInnerHTML`로 표시하지 않는다.

한국어 달력 표현은 span을 만들기 전에 연·월·일의 결합이 분명한 형식으로 바꾼다.

| 원문 형태 | 번역용 보호 값 | 보존 기준 |
| --- | --- | --- |
| `2026년 11월 3일` | `2026/11/3` | 연·월·일의 값과 순서 보존 |
| `10월 28일~11월 3일` | `10/28~11/3` | 각 월·일 값과 범위 보존 |
| `2026년 01월 03일` | `2026/01/03` | 원문 앞자리 0도 보존 |
| `2026-2`, `3.5`, `207`, `17:00–19:00` | 원래 숫자 리터럴 | 학기·학점·실번호·시간 리터럴 보존 |

날짜를 Date 객체로 다시 계산하거나 월/일 값을 추정하지 않는다. 이는 원문 저장값 변경이 아니라 번역 요청의 표시 형태 정리다. 최초 HTML 적용안은 숫자 검증은 통과했지만 `11 3 , 2026`, `between 10 28 and 11 3`처럼 달력 구분이 사라졌다. 이 결과를 성공 품질로 덮지 않고 `real-provider-local-v3-initial.json`으로 보존한 뒤 v4의 날짜 결합을 보완했다.

### 검증 거부된 숫자 필드만 한 번 복구

`requestTranslations`는 provider 호출 전 입력 크기·일일 예산 예약과 응답 크기/형식 검증을 공통으로 적용한다. 첫 HTML 응답을 필드별로 복원하며, 숫자가 있는 필드 중 복원 검증에 실패한 필드만 새 text 보호 토큰으로 한 번 재요청한다. 이미 성공한 필드를 다시 보내지 않는다.

첫 호출과 fallback 호출은 **같은 12초 AbortSignal**을 공유한다. 새 12초를 붙여 총 대기 시간을 24초로 늘리지 않는다. 각 provider 호출은 별도로 전송량을 예약하며, 두 번째 호출도 잔여 한도를 넘으면 거부한다. 정상 HTML 응답까지 반환된 이후의 숫자 검증 실패에만 이 복구가 적용되며, 공급자 HTTP 오류·응답 형식 오류·timeout을 무조건 재시도하는 기능은 아니다.

fallback도 실패하면 기존 실패 처리로 원문을 제공하고 실패 신규 캐시의 lease를 정리한다. 성공한 다른 필드는 fallback 요청에서 제외되지만, 공유 batch의 최종 성공 캐시 저장은 전체 검증이 끝난 뒤 실행한다. 이 내부 1회 복구와 사용자가 누르는 Retry를 구분한다.
## 캐시와 비용·보안 경계

숫자가 있는 한글 필드만 `google-v2-nmt-ko-en-html-numbers-4`를 사용한다. 숫자가 없는 필드는 기존 `google-v2-nmt-ko-en-numbers-2`를 유지해 정상 캐시를 불필요하게 재번역하지 않는다.

- 구버전 숫자 필드 캐시와 숫자가 포함된 legacy request cache를 새 방식의 결과로 승격하지 않는다. 이전 문서는 삭제하지 않으며 기존 만료 정책에 맡긴다.
- 숫자 없는 유효 캐시의 재사용·공유·기존 만료 시각을 유지한다. 캐시 버전을 바꿨다는 이유로 모든 필드를 무효화하지 않는다.
- 원문 최대 6,000자, 확장된 provider 입력 최대 12,000자, 응답 크기 제한과 공개 source/field allowlist를 유지한다.
- 첫 HTML 호출과 제한된 text fallback 호출 각각 전에 기존 Firestore 일일 예산을 예약한다. HTML 보호 태그를 포함한 실제 전송 문자수가 예약에 반영되므로 태그 추가가 무료라고 계산하지 않는다. 원문 길이만으로 비용을 추정하지 않는다.
- provider/검증/캐시 저장 실패 후에도 이미 잡은 사용량 예약은 유지한다. 실패 신규 캐시의 lease는 정리하며 반복 Retry로 일일 한도를 우회할 수 없게 한다.
- HTML 모드 역시 Google 번역 요청이다. 로컬의 예약량은 앱이 관측한 수치이며 최종 Google 청구 문자수·청구액을 증명하지 않는다. 공유 캐시 hit와 실제 provider 호출 결과를 구분한다.
- 임의 원문, 비공개 입력, 교수명 등 기존에 제외하던 값은 새로 번역 대상에 넣지 않았다. 비밀값·API 키를 결과나 문서에 기록하지 않는다.

## 오류 안내와 복구 범위

`PageTranslationStatus`는 페이지 기본 사용 시 기존 전역 상태를 유지한다. 팝업은 자신의 번역 결과를 넘겨 해당 팝업의 loading/성공/오류만 표시한다. 따라서 공지 한 건의 실패를 이미 번역된 팝업 자체 실패로 표시하지 않는다.

팝업의 Retry는 같은 source kind/id/category에 속한 실패만 재시도한다. 페이지 Retry는 기존처럼 페이지의 활성 실패 항목을 복구한다. 원문 유지, 언어 변경 후 늦은 응답 무시, 재시도 전 지속되는 상태 문단으로 초점 이동, 닫기/Escape·초점 트랩은 유지한다. 새 글별 번역 버튼을 추가하지 않는다.

## 확인한 근거와 현재 한계

### 실제 Google 응답: 로컬 성공

대상은 운영 공개 원문에서 읽은 동일 공지의 제목·AI 요약·기한이다. 검증용 resolver는 이 공개 원문으로 한정했고, 번역 본체의 Firestore 캐시·일일 예약·실제 Google 호출 경로를 사용했다. Next 런타임을 포함한 운영 API 전체를 호출한 검증과는 구분한다.

`output/playwright/english-translation-fix-20261027/real-provider-local.json`:

- 2026-10-27 17:42:41 KST, provider 호출 1회, Google HTTP 200.
- 세 필드 모두 복원·숫자 검증 성공, 앱 사용량 추가 예약 636문자.
- 기한 결과 `2026/11/3`, 요약의 `2026-2`, `3`, `10/28~11/3` 보존.
- 제목 결과 `Registration 2026-2 Semester Tuition Installment Payment 3 Installment Notice`.
- 업무 콘텐츠 변경 0. 정상 번역 경로의 캐시·사용량 기록은 발생할 수 있다.

기계 번역의 `3 installment` 같은 문법은 매끄럽지 않을 수 있다. HTTP 성공·숫자 무결성과 문장 전체의 의미·자연스러움을 같은 기준으로 취급하지 않는다. 번역 품질 전체가 검증됐다고 주장하지 않는다.

### 실제 점검 팝업: HTML 거부 후 text 복구 성공

`output/playwright/english-translation-fix-20261027/real-provider-popup.json`은 2026-10-27 17:55:58 KST의 실제 Google 두 응답을 보존한다. 기존 공개 점검 팝업의 `description` 한 필드만 대상으로 했다.

1. 첫 HTML 호출 자체는 200이었다. Google이 보존 span 밖에 `October 27`을 추가해 원문 숫자 보존 검증이 응답을 거부했다. 이를 지우거나 검증을 느슨하게 만들지 않았다.
2. 거부된 한 필드만 text 보호 토큰으로 재요청했다. 두 번째 실제 Google 응답도 200이었고 토큰·숫자 검증을 통과했다.
3. 최종 문구에는 `2026.10.27(Tue) 17:00–19:00(KST)`가 원문 값 그대로 남았다. 두 호출 합계 추가 예약은 409문자, 업무 콘텐츠 변경은 0이었다.

이 결과는 실제 provider 내부 fallback의 성공이며, 브라우저 첫 응답을 임의 503으로 만드는 오류 UI fixture와는 다르다. 409문자와 공지 표본의 636문자를 전체 서비스의 과금액으로 합산·추정하지 않는다.
### 모의 provider 회귀와 오류 복구

최종 관련 7파일 103테스트(서버 41테스트)의 단위·컴포넌트 회귀는 모의 provider 응답으로 통과했다. 이전 99테스트 결과와 합산하지 않는다. 이 결과를 실제 공급자 정상 증거와 합산하지 않는다. 검사 범위는 실제 실패 패턴의 새 숫자 거부, 보호 숫자 재배열·학점·실번호, 달력 구분, 원문 escape/단일 decode, 보호 token 주변 엔티티가 52를 4로 재해석하거나 새 숫자를 숨기는 두 경계 거부, 구버전 숫자 캐시 배제·비숫자 캐시 재사용, 거부된 숫자 필드만 1회 fallback·동일 AbortSignal·fallback 예산 제한, 팝업/페이지 오류 범위 및 재시도 초점이다.

첫 실패를 503으로 제어한 브라우저 화면은 오류 복구 fixture다. 제어를 해제한 뒤 실제 앱 API로 성공한 화면과 구분해 기록해야 한다. 아직 실제 브라우저·새 배포의 복구까지 완료한 것으로 판정하지 않는다.

별도 전체 unit 실행은 357,818ms 후 exit 0으로 끝났지만 최종 fallback 보완 전 소스였다. 이를 최종 코드 전체 회귀 성공으로 사용하지 않는다. 최종 lint·타입과 프로덕션 빌드 `Y3yYJzwJnGZjXriu2qewu`를 통과했으며, 정확한 최종 PR head의 필수 CI와 배포 이후 검증을 이어 확인한다.

## 공급자 문서와 적용 한계

[Cloud Translation Basic 번역 문서](https://docs.cloud.google.com/translate/docs/basic/translating-text)는 HTML 입력에서 태그와 사이의 텍스트를 다루는 방식을 설명한다. [`translate: translate` v2 REST 문서](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate)는 `format`의 text/html을 정의한다.

[번역 문제 해결 문서](https://docs.cloud.google.com/translate/troubleshooting)의 `translate="no"`/`notranslate` 설명은 Advanced 문맥을 포함한다. 이를 Basic v2의 모든 응답에서 마크업·숫자를 반드시 그대로 돌려준다는 보증으로 확대하지 않았다. 이번 Basic v2 실제 표본에서는 보호 span이 유지되는 것을 확인했으며, 다른 응답이 변형되면 앱 검증이 거부하도록 한다. 실제 팝업에서 관찰된 HTML 숫자 추가는 text 방식으로 한 번만 복구하되 같은 검증을 다시 통과하도록 한다.

[Google 번역 요금 안내](https://cloud.google.com/translate/pricing)를 실제 청구 기준으로 확인해야 한다. HTML 보호로 provider 전송량이 늘 수 있으므로 숫자 없는 캐시는 재사용하고, 앱은 보호 마크업을 포함한 전송량을 예산에 반영한다. 공지 636문자·팝업 409문자 예약을 최종 청구액이나 전체 서비스 비용으로 해석하지 않는다.
