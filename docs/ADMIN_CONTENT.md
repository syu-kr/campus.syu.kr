# 관리자 대시보드와 공지·배너 운영

`/admin`에서 대시보드, 서비스 공지, 배너, 문의·제보, 룸메이트 관리를 이용한다. 학교에서 수집하는 공지 원본을 수정하는 화면은 아니다. 기존 접수 상태·검색·분류·룸메이트 관리 기능은 각각의 메뉴에 유지한다.

## 작성과 게시

- **초안 저장**은 작성 내용만 저장한다. 현재 게시본과 배너 닫기 기록은 바뀌지 않는다.
- **게시 검토**에서 실제 내용과 이미지를 확인한 뒤 게시한다. 시작·종료 시간은 한국시간으로 입력한다. 시작 전은 예약, 종료 후에는 노출하지 않는다.
- **노출 중단**은 게시본을 숨기고 초안은 보존한다. **보관**도 되돌릴 수 있으며, 보관 해제만으로 다시 게시되지는 않는다.
- 다른 관리자가 먼저 수정하면 현재 입력을 유지하고 충돌을 안내한다. 목록을 다시 확인한 뒤 편집한다. 네트워크·토큰 확인 시간이 초과되어도 입력을 유지하며 재시도할 수 있다.
- 로그아웃·계정 변경·권한 상실 시 비공개 목록과 작성 중인 내용을 화면에서 제거한다. 저장하지 않은 내용을 다른 항목으로 바꿀 때는 확인한다.

서비스 공지는 제목·요약·Markdown 본문과 선택적인 영문본을 작성한다. 한국어를 바꾸고 영문을 그대로 둔 경우, 게시 전 영문도 검토했음을 확인하거나 영문을 비워야 한다. 검토하지 않은 과거 번역을 새 한국어 공지에 자동 연결하지 않는다.

기존 Markdown 공지 19개는 기본 게시본으로 유지하며, 관리자가 수정하면 같은 주소의 관리 저장본을 사용한다. 새 공지는 고유한 주소를 사용하고 게시 후 목록·홈·사이트맵에 반영된다. 게시 중단·보관된 주소는 404를 반환하되 언어와 목록 페이지 복귀를 유지한다.

## 배너

안내, 행사·모집, 광고·제휴를 구분하고 홈 또는 사이트 상단에 배치한다. 광고는 광고 표시와 외부 광고 링크의 sponsored 속성을 제공한다. 임의 광고 스크립트나 자동 회전은 실행하지 않는다.

- 큰 우선순위 숫자부터 정렬하며 위치별 최대 3개를 표시한다.
- 홈 배너는 기본 이미지가 필요하고 모바일 이미지는 선택 사항이다. 사이트 상단은 텍스트 배너도 가능하다.
- 이미지가 있으면 대체 설명을 입력한다. 연결 주소는 사이트 내부 경로 또는 https만 허용한다.
- 닫기·오늘 그만 보기는 별도 동작이다. 오늘 숨기기는 한국시간 자정까지 유지한다. 게시본이 바뀌면 다시 안내하고, 초안만 저장하면 숨김 기록은 그대로다.
- 이미 열린 정상 통신 화면에서는 30초 간격으로 새 게시본·예약 시작을 확인한다. 종료 시각에는 로컬 타이머로 숨긴다. 신규 조회는 서버에서 현재 게시 기간을 검사한다.

## 이미지와 저장소

PNG·JPEG·WebP를 최대 5MiB까지 업로드할 수 있다. 서버에서 실제 파일 형식과 2,500만 픽셀 제한을 검사하고 EXIF를 제거한다. 최대 1920px로 줄여 WebP로 저장하며 결과는 2MiB 이하다. 파일 이름은 서버가 생성한 UUID이며 기존 파일을 덮어쓰지 않는다.

이미지는 공개용 자산이다. 업로드 후에는 게시 여부와 관계없이 이미지 주소로 볼 수 있다. 배너 노출 중단이 파일 주소를 즉시 회수하는 것은 아니므로 비공개 자료나 개인정보를 업로드하지 않는다. 미사용 업로드를 자동 삭제하는 기능은 포함하지 않았다.

Firebase Storage 버킷은 미리 존재해야 한다. `MANAGED_CONTENT_STORAGE_BUCKET`이 있으면 서버에서 우선 사용하고, 없으면 기존 `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`을 사용한다. 관리자 화면은 버킷 메타데이터 조회가 가능한지 확인하며 404·권한 오류·시간 초과에는 업로드를 차단한다. 이 읽기 검사가 실제 업로드 권한까지 증명하지는 않는다.

2026-10-26 설정 전 점검에서는 버킷이 없었으나, 사용자가 Storage를 설정한 뒤 같은 날 실제 관리자 업로드를 재검증했다. 개인 정보 없는 합성 PNG 한 건이 200으로 업로드됐고, 공개 경로에서 80×40 WebP·EXIF 제거·immutable 캐시·ETag 조건부 304를 확인했다. 시험 객체만 generation을 대조해 삭제했다. 미인증 업로드는 401이었다. 버킷은 미국 동부, Firestore는 서울 리전이므로 공개 데이터 이전의 cold 성능을 별도로 측정한다. 기존 파일이나 버킷·요금제는 변경하지 않았다. [Firebase Storage 설정](https://firebase.google.com/docs/storage/admin/start)

## 접근과 데이터

- Firebase ID 토큰과 서버 `ADMIN_UIDS`로 관리자 권한을 확인한다. 관리자 API는 비로그인 401, 허용하지 않은 UID 403으로 닫힌다.
- `RATE_LIMIT_SECRET`은 기존 영속 요청 제한에 필요하다. 설정·토큰·허용 UID의 실제 값은 문서나 공개 저장소에 넣지 않는다.
- 편집 기록은 Firestore `site_managed_content`에 저장한다. 초안과 게시본, 편집 revision과 게시 revision을 분리한다. 읽기·쓰기·이미지 요청에 각각 제한을 둔다.
- 관리 저장본은 최대 500개이며 초과 신규 생성은 명시적으로 차단한다. 기존 항목 수정은 가능하다. 원본 Markdown 기본 공지는 별도로 유지한다.
- 공개 목록은 초안 본문과 국·영문 공지 본문을 읽지 않는 metadata projection을 사용한다. 상세는 공개 ID 한 건의 게시본만 읽는다.
- 공개 캐시는 30초이며 게시·중단·보관 시 즉시 무효화한다. 저장소 오류 때 숨긴 원본 공지를 다시 보여주지 않는다. 배너 조회 실패는 캠퍼스 서비스 전체를 막지 않고, 홈 공지 실패는 해당 영역에서 복구한다.
- 브라우저의 Firestore 직접 접근을 허용하지 않는다. 기존 기본 거부 규칙과 서버 Admin SDK 경계를 유지한다.

## 검증 경계

공지·배너 저장·게시와 실패 흐름은 모의 데이터로 검증했다. 실제 허용 계정으로 인증·조회 및 위 합성 이미지 한 건의 업로드·공개 조회·삭제를 확인했다. 기존 운영 공지·배너·문의·파일을 시험 재료로 수정하지 않았다. 인증 로그인 기록과 API 요청 제한 카운터는 검증 과정에서 갱신될 수 있다.

운영 배포와 운영 도메인의 업로드 확인은 별도 작업이다. 배포 환경에도 동일 프로젝트의 `ADMIN_UIDS`, `RATE_LIMIT_SECRET`, Firebase Admin 및 Storage 설정을 등록해야 한다. 로컬 `.env.local` 설정이 운영 환경에 자동 반영되지는 않는다.
