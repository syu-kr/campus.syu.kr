# 관리자 대시보드와 공지·배너 운영

`/admin`에서 대시보드, 서비스 공지, 배너, 문의·제보, 룸메이트를 관리한다. 학교에서 수집한 공지 원본을 수정하는 화면은 아니다. 기존 접수 상태·검색·분류·룸메이트 관리 기능은 각각의 메뉴에 유지한다.

## 작성과 게시

- **초안 저장**은 작성 내용만 저장한다. 현재 게시본과 배너 닫기 기록은 바뀌지 않는다.
- **게시 검토**에서 실제 내용과 이미지를 확인한 뒤 게시한다. 시작·종료 시간은 한국시간으로 입력한다. 시작 전은 예약, 종료 후에는 노출하지 않는다.
- **노출 중단**은 게시본을 숨기고 초안은 보존한다. **보관**도 되돌릴 수 있으며, 보관 해제만으로 다시 게시되지는 않는다.
- 다른 관리자가 먼저 수정하면 현재 입력을 유지하고 충돌을 안내한다. 목록을 다시 확인한 뒤 편집한다. 네트워크·토큰 확인 시간이 초과되어도 입력을 유지하며 재시도할 수 있다.
- 로그아웃·계정 변경·권한 상실 시 비공개 목록과 작성 중인 내용을 화면에서 제거한다. 저장하지 않은 내용을 다른 항목으로 바꿀 때는 확인한다.

서비스 공지는 제목·요약·Markdown 본문과 선택적인 영문본을 작성한다. 한국어를 바꾸고 영문을 그대로 둔 경우, 게시 전 영문도 검토했음을 확인하거나 영문을 비워야 한다. 검토하지 않은 과거 번역을 새 한국어 공지에 자동 연결하지 않는다.

기본 hybrid 모드에서는 기존 Markdown 공지를 기본 게시본으로 유지하고 같은 주소의 관리 저장본을 우선한다. `SERVICE_NOTICES_SOURCE=database`에서는 DB 단독 조회 계약을 사용한다. 새 공지는 고유한 주소를 사용하고 게시 후 목록·홈·사이트맵에 반영된다. 게시 중단·보관된 주소는 404를 반환하되 언어와 목록 페이지 복귀를 유지한다. 원문·검수 영문·URL·최초 날짜·작성자·번호의 이전과 삭제 조건은 [공지 이전](SERVICE_NOTICE_MIGRATION.md)과 [전환 절차](FIREBASE_CUTOVER.md)를 따른다.

## 배너와 팝업

안내, 행사·모집, 광고·제휴를 구분하고 **노출 위치**에서 홈 카드 배너, 사이트 상단 안내, 팝업 공지를 선택한다. 광고는 광고 표시와 외부 링크의 sponsored 속성을 제공한다. 임의 광고 스크립트나 자동 회전은 실행하지 않는다.

- 큰 우선순위 숫자부터 정렬하며 위치별 최대 3개를 표시한다. 팝업은 한 번에 하나씩 표시한다.
- 홈 배너는 기본 이미지가 필요하고 모바일 이미지는 선택 사항이다. 사이트 상단은 텍스트 배너도 가능하다. 이미지에는 대체 설명을 입력하며 연결 주소는 사이트 내부 경로 또는 https만 허용한다.
- 팝업은 항상 닫을 수 있다. 관리자 닫기 허용은 선택 상태로 고정되며 서버도 같은 규칙을 적용한다. 이미지 전체를 contain으로 표시하고 좁은 화면에서는 본문을 스크롤하며 하단 버튼에 계속 접근할 수 있어야 한다.
- **닫기**, Escape, 배경 클릭은 같은 탭의 sessionStorage에 기록한다. **오늘 그만 보기**는 localStorage에 한국시간 다음 자정까지 기록한다. 키는 `campus-banner:<id>:<revision>`이며 새 게시 revision은 다시 안내하고 초안 저장만으로는 기록이 바뀌지 않는다.
- 저장소가 막혀도 현재 화면에서 닫을 수 있다. 기록을 읽기 전에 팝업을 잠깐 열거나 이미 숨긴 이미지에 preload를 걸지 않는다. 관리자·룸메이트·개별 일정 방에서는 공개 배너를 조회·표시하지 않으며 SPA 이동 시 경로를 다시 확인한다.
- 초기 SSR의 닫힌 native dialog는 nonce bootstrap과 기본 레이아웃 셸 마커로 준비를 확인한다. 마커가 없으면 DOMContentLoaded 경로를 유지한다. 전체 Suspense 콘텐츠나 앱 hydration 완료를 뜻하는 마커가 아니다.
- 다른 dialog가 먼저 열렸으면 이미지도 요청하지 않는다. 나중 dialog가 나타나면 양보하고 닫힌 뒤 다시 표시할 수 있다. 이미 정상 노출하면서 시작한 요청을 소급 취소한다는 의미는 아니다.
- 초기/완료 후 Tab·Shift+Tab 초점 제한, 닫기·Escape·배경 클릭, React handoff와 닫은 뒤 초점 복귀를 확인한다. native dialog는 DOM에서 제거하기 전에 닫는다. JS 비활성 환경에서 팝업으로 서비스 이용을 막지 않는다.
- English 팝업은 자신의 번역 상태·Google 표기·실패 재시도를 표시한다. 다른 공지의 실패를 해당 팝업 번역 실패로 표시하지 않는다.
- 이미 열린 정상 통신 화면에서는 30초 간격으로 새 게시본·예약 시작을 확인한다. 종료 시각에는 로컬 타이머로 숨긴다. 신규 조회는 서버에서 현재 게시 기간을 검사한다.

공개 배너 첫 조회의 빈 목록 fallback과 초기 JS·폰트 비용은 후속 분석 대상이다. warm 팝업 성능 결과를 서버 cold 조회·실기기 성능의 보장으로 읽지 않는다. [성능 가이드](../PERFORMANCE.md)와 [유지보수 경계](MAINTENANCE.md)를 함께 확인한다.

## 이미지와 저장소

PNG·JPEG·WebP를 최대 5MiB까지 업로드할 수 있다. 서버에서 실제 파일 형식과 2,500만 픽셀 제한을 검사하고 EXIF를 제거한다. 최대 1920px로 줄여 WebP로 저장하며 결과는 2MiB 이하다. 파일 이름은 서버가 생성한 UUID이며 기존 파일을 덮어쓰지 않는다.

이미지는 공개용 자산이다. 업로드 후에는 게시 여부와 관계없이 주소로 볼 수 있고 공개 응답에는 1년 immutable 캐시가 적용된다. 배너 노출 중단이 객체·이미 알려진 주소·내려받은 캐시를 즉시 회수하지는 않는다. 비공개 자료나 개인정보를 업로드하지 않는다. 미사용 업로드를 자동 삭제하는 기능은 포함하지 않았다.

Firebase Storage 버킷은 미리 존재해야 한다. `MANAGED_CONTENT_STORAGE_BUCKET`이 서버에서 우선하고 없으면 `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`을 사용한다. 관리자 화면은 버킷 메타데이터를 읽을 수 있는지 확인하며 404·권한 오류·시간 초과에는 업로드를 차단한다. 이 읽기 검사만으로 실제 업로드 권한까지 증명하지 않는다. [Firebase Storage 안내](https://firebase.google.com/docs/storage/admin/start)

## 접근과 데이터

- 폐기 여부를 확인한 Firebase ID token과 서버 `ADMIN_UIDS`로 권한을 확인한다. 비로그인 401, 허용하지 않은 UID 403, 유효 토큰 뒤 관리자 설정 누락은 503으로 닫힌다.
- `RATE_LIMIT_SECRET`은 영속 요청 제한에 필요하다. 실제 UID·비밀값을 코드·문서·로그에 넣지 않는다. Production/Preview의 프로젝트·UID·버킷·권한 범위를 별도로 확인한다.
- Firestore `site_managed_content`에서 초안과 게시본, 편집 revision과 게시 revision을 분리한다. 읽기·쓰기·이미지 요청은 각각 제한한다.
- 관리 저장본 최대 500개를 넘는 신규 생성은 명시적으로 차단하며 기존 항목 수정은 가능하다. hybrid 원본 Markdown 공지는 별도다.
- 공개 목록은 초안 및 국·영문 본문을 읽지 않는 metadata projection을 사용한다. 상세는 공개 ID 한 건의 게시본만 읽는다.
- 공개 캐시는 30초이며 게시·중단·보관 시 무효화한다. 저장소 오류 때 숨긴 원본 공지를 다시 보여주지 않는다. 배너 조회 실패로 캠퍼스 서비스 전체를 막지 않고 홈 공지 실패는 해당 영역에서 복구한다.
- 브라우저 Firestore 직접 접근을 열지 않고 기본 거부 규칙과 서버 Admin SDK 경계를 유지한다.

## 운영 확인

허용 계정 인증·조회, 미인증/미등록 거부·revoke, 비민감 시험 이미지 업로드·WebP/EXIF·GET/304·실제 화면을 각각 확인한다. 버킷 읽기 성공이나 모의 저장·게시 테스트를 실제 쓰기 성공으로 대신하지 않는다. 시험 객체를 삭제할 때는 해당 UUID·generation을 대조한다.

신규 공지·팝업의 실제 게시, 예약 시작·종료, CDN·서버 캐시 반영과 운영 문의 접수는 승인한 범위에서 검증한다. 일반 사용자에게 알림을 보내거나 기존 운영 콘텐츠를 시험 재료로 수정하지 않는다. 로컬 환경 설정은 운영에 자동 반영되지 않으며 실제 전환·배포는 별도 절차다.
