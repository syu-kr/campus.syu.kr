## 준비와 시험 순서

학생 A는 글 작성자, 학생 B는 다른 학교 이메일을 인증한 조회·신고자다. **신고·타인 권한 시험에는 서로 다른 학교 이메일을 가진 인증 학생 2명이 필요하다.** 같은 이메일을 다른 브라우저에서 인증하면 같은 작성자로 취급되므로 B를 대신할 수 없다. 관리자 권한이 있는 운영 담당자는 별도로 필요하다. 한 사람이 학생 A와 관리자 역할을 수행할 수 있다.

시험 글에는 `기능 확인용 시험 글`처럼 목적을 표시하고, 본인 소유의 시험용 카카오 오픈채팅을 사용한다. 실명·전화번호·호실·학교 이메일은 글에 넣지 않는다. 시험 종료 시 글을 완료하거나 삭제하고 관리자 보류도 해제한다. 신고 근거와 감사 기록은 보존 정책에 따라 남으므로 수동으로 전체 자료를 지우지 않는다.

| 순서 | 환경 | 필요한 사람 | 확인할 범위 |
| --- | --- | --- | --- |
| 1 | 운영 HTTPS, PC Chrome 또는 Edge의 비인증 창 | 운영 담당자·A | 배포·메뉴·공지·비인증 접근 |
| 2 | PC Chrome 또는 Edge, 학교 메일함 | A | 최초 인증·재방문·작성·수정·필터·연락 |
| 3 | 별도 PC 프로필 또는 다른 기기 | B와 A | 타인 조회·수정 차단·신고 |
| 4 | PC의 `/admin` | 관리자와 A | 신고 처리·숨김·복구·작성 보류·인증 분리 |
| 5 | 실제 Android Chrome 또는 iPhone Safari와 메일 앱 | A 또는 B | 메일 앱에서 브라우저 전환·키보드·재방문·로그아웃 |
| 6 | 실제 카카오 인앱 브라우저 | A 또는 B | 인앱 진입·일반 브라우저 전환·저장소 차이 |
| 7 | 홈 화면에 설치한 웹앱 | A 또는 B | 설치 상태의 인증·재방문·오프라인 비공개 |
| 8 | Vercel·Firebase·Actions 운영 화면 | 운영 담당자 | 권한 경계·관측·중지·복구·정상 예약 정리 |

### 메일 발송을 아끼는 방법

이전 Spark 상태의 로그인 링크 발송 한도는 하루 5통이었다. 이후 사용자가 Blaze 전환 완료를 알렸으며, 2026-10-04 운영 프로젝트 `syu-campus`의 Firebase Console에서도 **Blaze**를 확인했다. 현재 [Firebase 공식 한도](https://firebase.google.com/docs/auth/limits)의 로그인 링크 기본 발송 기준은 **하루 25,000통**이다. 이 한도는 앱의 이메일별 재발송·일일 제한과 별개이며, 사용자 수에 따른 조정이나 의심 트래픽에 대한 남용 방지 제한이 추가될 수 있다. 현재는 이전 하루 5통 제한 때문에 시험을 여러 날로 나눌 필요가 없다. 실제 제공자 오류가 발생하면 해당 오류와 시험 상태를 기록한다.

1. 먼저 A·B의 PC 인증에 각 1통을 사용하고 글·신고·admin 시험 동안 로그아웃하지 않는다. 이미 유효한 세션이 있으면 다시 발송하지 않는다.
2. 모바일, 설치 웹앱, 카카오 인앱의 실제 인증을 순서대로 진행한다. 각 환경은 저장소가 달라 추가 메일이 필요할 수 있다. PC Edge 인증도 Chrome과 별도 세션이면 추가 발송이 필요하다.
3. PC·모바일·앱 시험마다 반복 발송하지 않는다. 로그인 링크 재사용 오류는 이미 소비한 링크로 시험할 수 있으며 새 발송이 필요하지 않다. 완료된 링크는 인증을 공유하는 방법으로 사용할 수 없다.
4. 실제 재발송은 최소 60초를 기다리고 한 번만 확인한다. 실제 만료 링크 시험은 필요한 시간이 경과한 뒤 확인한다. 제공자 제한 오류가 나면 반복 요청을 멈추고, 실제 가능 여부를 확인한 뒤 이어간다. 제공자의 한도 갱신 시각을 한국 시간 0시라고 가정하지 않는다.
5. 발송 제한이 걸려도 기존 유효 세션은 계속 이용할 수 있어야 한다. 실제 제한이 발생해 추가 인증을 시험하지 못한 경우에만 `미실행: 제공자 제한`으로 기록한다.

## 1. 배포 직후와 비인증 접근

| 확인 | 통과 기준 |
| --- | --- |
| [ ] 캠퍼스 메뉴에서 게시판 진입 | `룸메이트 구하기` 메뉴가 있고 올바른 운영 주소로 이동한다. 준비 안내·404·반복 이동이 없다 |
| [ ] 공지와 실제 기능 비교 | 공개 공지의 제목·본문·게시판 링크가 표시되고 링크에서 인증을 시작할 수 있다. 공지 없음 화면의 HTTP 200을 공개 성공으로 세지 않는다 |
| [ ] Chrome·Edge의 새 비인증 창에서 목록·작성·내 글·시험 글 상세 직접 열기 | 인증 화면 또는 접근 안내가 나오며 글 본문·생활습관·카카오 링크가 보이지 않는다 |
| [ ] 비인증 상태로 `/admin` 진입 | 기존 관리자 인증이 필요하고 학생 자료·신고함이 보이지 않는다 |
| [ ] 한국어·영문 페이지 | 선택한 언어와 경로가 일치하고 사용자가 작성한 소개글은 원문으로 표시한다 |

운영 담당자는 이 단계에서 실제 Production 배포의 소스 SHA·배포 ID, 세 플래그, 운영 도메인·Rules·필수 인덱스 4개 READY를 기록한다. 비밀값은 값 원문 없이 등록 여부와 환경 범위만 기록한다. 인덱스 미준비나 서버 오류를 빈 목록으로 판정하지 않는다.

## 2. PC Chrome·Edge와 실제 메일

| [ ] 이미 사용한 링크 다시 열기 | 새 세션을 발급하지 않고 사용할 수 없는 링크 안내와 새 인증 경로를 제공한다 |
| [ ] 실제 재발송·만료 링크 | 60초 이내 재요청은 제한되고, 실제 만료된 링크는 인증되지 않는다. Firebase의 만료 시간을 임의로 5분 등으로 정하지 않는다. 미실행이면 그대로 남긴다 |

| [ ] 메뉴와 키보드 조작 | 모집글·글 작성·내 글의 활성 메뉴에 밑줄이 표시된다. Tab 초점이 보이고 Enter로 이동한다. 일반 클릭 때 불필요한 버튼 윤곽선이 지속되지 않는다 |

30일 유지와 12시간 선택은 고정 수명이다. 당일 재방문 시험은 30일 전체 경과 시험을 대신하지 않는다. 12시간 선택 해제는 아래 모바일 인증 때 함께 시험해 추가 발송을 줄인다.

## 3. 글 작성·두 학생의 조회·신고·권한

등록→B의 조회·권한·신고→다음 절의 관리자 처리 순서로 진행한다. 아래 모집 완료·새 모집·삭제 항목은 관리자 처리까지 마친 뒤 수행한다. 동시 등록을 시험하려면 최초 등록 전에 작성 화면 두 탭을 준비하고 두 탭에서 한 번씩 제출한다.

| 확인 | 환경·담당 | 통과 기준 |
| --- | --- | --- |
| [ ] 필수 조건과 잘못된 입력 | A의 PC | 기숙사·인실·인원·날짜 조합을 검증한다. 빈 닉네임·지난 거주 종료일·기간 역전·인원 초과·잘못된 연락 링크는 등록되지 않고 해당 필드로 안내한다 |
| [ ] 글 1개 등록 후 내 글 확인 | A의 PC | 한 번만 등록되고 목록·내 글·상세의 조건과 마감일이 일치한다. 미기재 습관과 `상관없음`을 구분한다 |
| [ ] 두 탭에서 동일 작성자의 동시 등록 | A의 PC, 최초 등록 전에 준비 | 활성 글은 하나만 생긴다. 다른 요청은 중복 안내로 종료한다. 운영의 신규 등록·요청 제한을 고려해 반복하지 않는다 |
| [ ] 목록 필터·상세·뒤로가기 | A 또는 B | 필터 조건에 맞는 글을 보여주며 뒤로가기 때 조건을 복원한다. 실제 다음 페이지가 있으면 더 보기에서 중복·누락을 확인한다. 자료가 부족하면 페이지 경계는 미실행으로 남긴다 |
| [ ] 소개·생활습관 수정과 오래된 탭의 저장 | A의 두 탭 | 저장한 새 내용이 반영된다. 오래된 버전의 저장이 최신 내용을 조용히 덮어쓰지 않고 충돌 안내를 제공한다. 수정으로 최초 등록 시각이나 모집 기간이 연장되지 않는다 |
| [ ] 다른 학생의 조회와 카카오 연결 | **인증 학생 B**, A의 글 | 목록·상세를 읽고 A가 설정한 시험 오픈채팅으로 이동한다. 일반 학생에게 작성자의 학교 이메일이나 신고자 신원을 공개하지 않는다 |
| [ ] 타인의 수정·삭제·완료 거부 | **인증 학생 B**, A의 글 | 본인 관리 버튼이 없고 타인의 편집 주소로 진입해도 조치할 수 없다. 운영 담당자의 시험 요청에서도 403 등 권한 거부이며 A의 글이 바뀌지 않는다 |
| [ ] 자기 글 신고 차단 | A | 자기 글을 신고할 수 없다 |
| [ ] 최초 신고·중복 신고 | **인증 학생 B**, A의 글 | 신고 사유를 제출하면 1건만 접수된다. 같은 글 재신고는 거부된다. 신고 자체로 자동 숨김·작성 보류가 걸리지 않는다 |
| [ ] 신고 뒤 A가 글 수정 | A·B·관리자 | 관리자에게 최초 신고 당시의 최소 근거가 보존된다. 현재 내용과 당시 근거를 혼동하지 않는다 |
| [ ] 모집 완료와 재방문 | A가 완료, B가 기존 상세 재방문 | B에게 소개·연락 링크를 더 제공하지 않고 종료 안내를 보여준다. A의 내 글에 완료 상태가 반영된다 |
| [ ] 새 모집·삭제 | A, admin 시험까지 끝난 뒤 | 완료 후 새 모집이 가능하다. 시험 글 삭제 후 다른 학생에게 내용·연락 링크가 보이지 않는다. 시험 글의 신규 등록 횟수 제한을 고려한다 |

카카오 연결은 시험용 방이 열리는지까지만 확인하며 다른 사람에게 메시지를 보내는 단계는 필요하지 않다. 동시 신고·수정·삭제 경합의 반복 시험과 일일 제한 초과를 위한 대량 등록은 [격리 통합 검사](../tests/roommate.integration.ts)에서 수행한다. 프로덕션에서는 위 최소 동작과 저장 결과를 확인한다.

## 4. `/admin` 관리와 학생 인증 분리

두 학생 시험 글을 완료·삭제하기 전에 관리자 단계를 진행한다. 관리자 조치는 시험 글과 A의 시험 작성자 상태에만 적용한다.

| 확인 | 통과 기준 |
| --- | --- |
| [ ] 기존 admin 로그인·글 및 신고 목록 | 룸메이트 관리에서 글·신고·미처리 수가 정상 조회된다. Firebase 인덱스 오류를 빈 화면으로 처리하지 않는다 |
| [ ] 신고 상태·처리 메모 변경 | 접수→검토→완료 또는 반려가 반영되고 처리 이력이 남는다. 신고 상태 변경만으로 글 상태가 바뀌지 않는다 |
| [ ] 글 숨김 | B의 목록·상세에서 내용·연락 링크가 사라지고 A의 신규 작성·내용 수정은 작성 보류 안내로 차단된다 |
| [ ] 숨긴 글 복구 | 모집 중이며 다른 활성 글이 없으면 다시 공개된다. **글 복구와 작성 보류 해제는 별도**로 동작한다 |
| [ ] 작성 보류 해제 | 해제 뒤 A의 허용된 작성·수정이 가능하다. 보류 중에도 본인 완료·삭제는 가능하다. 확인 후 시험 보류를 남기지 않는다 |
| [ ] 복구 불가 상태 | 마감·완료·삭제된 글이나 다른 활성 글이 있는 이전 글을 복구하지 않는다. 이 조건을 만들지 못한 경우 미실행으로 기록한다 |
| [ ] 신고 후 작성자가 글 삭제 | 신고 근거는 보존되어 관리자가 처리할 수 있다. 삭제된 글을 학생에게 다시 공개하지 않는다 |
| [ ] 같은 브라우저 admin 로그인 뒤 학생 인증·로그아웃 | 기존 admin 로그인과 FCM 이용 상태가 유지된다. 학생 로그인으로 관리자 계정을 덮어쓰거나 관리자 권한을 얻지 않는다 |
| [ ] 학생만 인증한 환경에서 admin 자료·API 접근 | 관리자 자료를 제공하지 않는다. 학생 쿠키만 있는 요청은 admin 인증 거부, 일반 학생 Firebase token은 관리자 권한 거부를 확인한다 |

보류 중 삭제→재인증→재등록 우회 검사는 추가 메일이 필요할 수 있다. 실행한 경우 보류가 유지되어야 한다. 개인의 실제 학교 Auth 계정을 임의로 비활성화·삭제·이메일 변경해 시험하지 않는다. 인증 폐기 검사는 동의한 전용 시험 계정 또는 독립 테스트 Firebase에서 수행하고 운영 확인 여부를 별도로 기록한다.

## 5. 실제 모바일과 메일 앱 → 브라우저

가능하면 Android Chrome과 iPhone Safari를 각각 수행한다. 기기 하나만 있으면 그 기기의 결과만 기록한다. PC viewport 변경은 실제 모바일 시험으로 세지 않는다.

| 확인 | 통과 기준 |
| --- | --- |
| [ ] 기종·OS·브라우저·메일 앱 기록 | 실제 사용 환경을 기록하고 단순히 `모바일`로만 적지 않는다 |
| [ ] 모바일에서 요청 후 메일 앱의 링크 열기 | 어떤 브라우저로 열렸는지 확인한다. 저장소가 다른 경우 학교 이메일 재입력 후 인증할 수 있다. 인증 완료 뒤 게시판으로 이동한다 |
| [ ] `30일 유지`를 해제해 인증 | 화면은 최대 12시간 유지라고 안내한다. 브라우저 종료만으로 로그아웃된다고 약속하지 않는다. 같은 환경에서 12시간 안의 재방문을 확인하고, 실제 12시간 경과 후 재인증 필요 여부는 별도 후속 결과로 기록한다 |
| [ ] 이메일·소개·날짜·생활습관 입력 | 이메일 키보드·자동완성이 동작하고 키보드가 열린 상태에서도 오류·저장 버튼에 접근할 수 있다. 한글 입력이 끊기거나 초점이 이동하지 않는다 |
| [ ] 좁은 화면·스크롤·뒤로가기·가로 보기 | 메뉴·필터·글·신고 창이 잘리거나 수평으로 밀리지 않는다. 닫기·확인·취소를 누를 수 있다 |
| [ ] 여러 탭에서 로그아웃·뒤로가기·새로고침 | 글·생활습관·카카오 링크가 남지 않고 인증 화면으로 전환한다. 다른 탭은 재조회 또는 포커스 복귀 시 이전 사용자 내용을 제거한다 |

## 6. 카카오 인앱 브라우저

1. 카카오에서 **게시판 주소만** 열어 인앱 환경을 확인한다. 실제 인증 링크나 인증 query를 대화로 전달하지 않는다.
2. 가능하면 인앱에서 학교 메일을 요청하고 메일 앱에서 링크를 열어, 완료된 브라우저와 최초 요청한 인앱의 차이를 기록한다.
3. 인앱으로 돌아가 재방문한다. 세션이 공유되지 않으면 인증이 필요한 상태여야 하며 일반 브라우저에서 이용하라는 안내·전환 경로가 동작하는지 확인한다. 한 브라우저에서 인증했다고 다른 저장소에 자동으로 로그인되어야 한다고 판정하지 않는다.
4. 일반 브라우저로 열기, 목록·상세·오픈채팅 이동과 뒤로가기를 확인한다. 반복 인증 요청·이동 루프·빈 화면이 없어야 한다.

- [ ] 인앱 최초 진입·브라우저 전환 확인
- [ ] 인앱 인증 또는 일반 브라우저 이용 경로 확인
- [ ] 실제 재방문·연락 링크 확인

## 7. 설치 웹앱

Android는 브라우저의 설치 기능, iPhone은 Safari의 홈 화면 추가로 설치한 뒤 앱 아이콘에서 연다. Android TWA 배포 앱을 별도로 이용한다면 설치 방식도 구분해 기록한다.

| 확인 | 통과 기준 |
| --- | --- |
| [ ] 설치 상태의 최초 진입과 인증 | 메일 링크가 설치 앱 또는 일반 브라우저 어디에서 완료되는지 기록한다. 공유되지 않는 경우 재입력·일반 브라우저 이용 경로가 동작한다 |
| [ ] 앱을 닫고 아이콘으로 재방문 | 그 앱에 유효한 세션이 생긴 경우 바로 진입한다. 다른 브라우저만 인증했다면 로그인 상태를 가정하지 않는다 |
| [ ] 설치 앱 로그아웃 후 재실행 | 이전 글·연락처가 보이지 않고 인증이 필요하다 |
| [ ] 비행기 모드·오프라인 재실행 | 이전 글 본문·생활습관·카카오 링크가 오프라인 캐시로 노출되지 않는다. 장애·오프라인을 빈 목록이나 로그인 성공으로 표시하지 않는다 |
| [ ] 온라인 복귀 | 무한 로딩 없이 다시 요청하거나 재시도할 수 있고 화면의 인증 상태가 서버와 일치한다 |

## 8. 운영 담당자: 권한·관측·중지·복구·예약 정리

이 단계는 사용자 개인 기기 시험과 별도로 운영 담당자가 실행한다. 네 컬렉션의 직접 접근, 민감값과 장기 보존·정리 경계는 화면만으로 통과 판정할 수 없다.

| 확인 | 환경과 통과 기준 |
| --- | --- |
| [ ] 실제 배포와 운영 설정 | Vercel Production 소스 SHA·배포 ID 확인. Firebase public/Admin/Actions 프로젝트 일치, 에뮬레이터 설정 없음, 독립 owner 비밀값의 안정적 유지, 운영 도메인 등록·Rules 배포·인덱스 4개 READY 확인 |
| [ ] 비인증·학생 인증의 Firestore 직접 접근 | 운영 Rules로 `roommate_sessions`, `roommate_posts`, `roommate_owner_state`, `roommate_reports`의 클라이언트 읽기·쓰기가 모두 거부된다. 존재하지 않는 시험 경로 등으로 확인하고 다른 이용자의 비공개 자료를 덤프하지 않는다 |
| [ ] HTML·RSC·API·캐시 | 비인증 응답에 글·연락 정보가 없다. 보호 페이지/API의 `private, no-store`, `noindex, nofollow`, `no-referrer`를 확인한다. 로그아웃 후 캐시에서도 이전 자료를 보여주지 않는다 |
| [ ] GA·Sentry·Vercel 요청 기록 | 인증 완료 화면이 GA에 전송되지 않고 이메일·OOB code·ID token·세션 cookie 원문이 기록되지 않는다. URL query 처리·로그 저장 설정과 실제 결과를 각각 확인한다. 원문을 보고서로 복사하지 않는다 |
| [ ] 실패·요청 제한 안내 | 401·403·409·429·503을 성공이나 빈 목록으로 오인하지 않는다. 실제 제공자 quota 오류 시 새 발송 제한을 안내하며 기존 세션을 로그아웃시키지 않는다. 운영에서 장애·quota 소진을 일부러 유발하지 않는다 |
| [ ] 쓰기 중지→재배포→복구 | `ROOMMATES_WRITES_ENABLED=false`에서 새 등록·내용 수정만 차단하고 조회·본인 완료/삭제·신고·인증·로그아웃을 유지한다. `true` 복구 후 실제 새 배포에서 다시 확인한다 |
| [ ] 발송 중지→재배포→복구 | `ROOMMATES_EMAIL_ENABLED=false`에서 사이트 새 발송만 차단하고 기존 유효 세션·미소비 유효 링크 완료·로그아웃을 유지한다. 미소비 링크 시험은 중지 전에 1통만 준비한다 |
| [ ] 전체 중지→재배포→복구 | `ROOMMATES_ENABLED=false`에서 메뉴·학생 조회·새 세션·발송을 차단한다. 로그아웃과 admin 사고 대응은 유지한다. 복구 뒤 HTTPS의 실제 동작을 확인한다 |
| [ ] 정상 예약 정리 | Actions의 `cleanup-expired-firestore.yml` 정상 예약 실행에서 새 코드 SHA·성공 여부·룸메이트 정리 카운터·오류를 확인한다. 예정은 한국 시간 03:30이지만 예약 실행은 지연될 수 있다 |
| [ ] 모집 마감과 물리 정리 분리 | 실제 시험 글의 마감 다음 날 한국 시간 0시 이후에는 정리 지연 중에도 학생에게 내용·연락 링크를 제공하지 않는다. 조회·로그아웃·재방문을 다시 확인한다 |
| [ ] 후속 보존 경계 | 세션 실제 12시간/30일 경과, 보류 30일, 신고 근거 30일, 감사 365일은 해당 기간 뒤 또는 격리 환경의 시간 경계 검사 결과로 구분한다. 아직 경과하지 않은 운영 시험은 미실행이다 |

중지 시험은 모든 이용자에게 영향을 주므로 운영 담당자가 시험 시각·범위를 기록하고 필요하면 안내한 뒤 수행한다. 플래그는 admin의 즉시 스위치가 아니라 **Vercel 환경 변경 후 새 배포**가 필요하다. 전체 중지·발송 중지 중 본인 삭제를 할 수 없는 사용자를 위한 외부 데이터 처리 문의 경로도 확인한다.

정리 스크립트는 다른 사이트 기능의 만료 자료도 실제 삭제하므로 **수동 실행을 시험 목적으로 사용하지 않는다.** 만료 후보·동시 수정·작성 보류·미처리 신고의 경계 시험은 격리 에뮬레이터에서 수행하고 운영에서는 정상 예약 실행을 관측한다. 기존 글·신고·세션·사용자 계정 전체 삭제, 운영 키 교체, 개인 계정의 인증 폐기를 테스트 초기화로 사용하지 않는다.

## 결과 기록과 오류 제보

체크는 실제 실행 후 표시하고 각 항목을 `통과 / 실패 / 미실행`으로 기록한다. 부족한 기기·두 번째 학생·발송 한도로 못 한 항목에는 이유를 붙인다. 실제 기기 미실행 항목을 자동 검사 통과로 바꾸지 않는다.

오류 제보는 아래 형식이면 재현하기 쉽다. URL은 query를 제거한 경로만 쓰고, 캡처에서 메일 주소·글의 개인정보·인증 링크·쿠키·token을 가린다. 메일 원문 링크, 서비스 계정, HMAC 키, 인증/세션 원문 또는 HAR 파일 전체를 붙이지 않는다.

```text
시험 항목: 예) 5-여러 탭 로그아웃
발생 시각: YYYY-MM-DD HH:mm KST
환경: 기종 / OS 버전 / Chrome·Edge·Safari 버전 / 메일 앱
실행 방식: 일반 브라우저 / 카카오 인앱 / 설치 웹앱
인증 상태: 미인증 / 학생 A / 학생 B / 관리자
30일 유지 선택: 켬 / 끔 / 해당 없음
경로: /campus/roommates/... (query 없이)
재현 순서: 1. ... 2. ... 3. ...
기대 결과: ...
실제 결과: 화면 문구·멈춤·반복 이동 등
재현 빈도: 매번 / N회 중 M회 / 한 번
참고: 개인정보와 인증값을 가린 화면 캡처
```

운영 담당자의 기록에는 소스 SHA·배포 ID·해당 HTTP 상태/안전한 오류 코드만 추가한다. 오류 수정 뒤에는 같은 기기·브라우저·로그인 상태로 해당 시험을 다시 수행하고 결과를 갱신한다.
