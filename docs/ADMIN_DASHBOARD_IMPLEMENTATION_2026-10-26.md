# 관리자 대시보드 구현·검증 — 2026-10-26

## 구현 범위

`/admin`을 대시보드·서비스 공지·배너·문의/제보·룸메이트의 다섯 화면으로 나눴다. 기존 문의 유형·검색·분류·상태 변경과 룸메이트 관리 흐름은 유지한다. 대시보드 수치는 실제 조회 항목과 접수 상태를 사용한다. 방문자 통계는 추가하지 않았다.

- 서비스 공지: 기존 19개 공지 유지, 신규 작성·수정, Markdown 미리보기, 선택적인 영문본, 초안 저장, 게시 검토, 예약·종료, 게시 중단, 보관·복원.
- 배너: 안내·행사/모집·광고/제휴, 사이트 상단/홈, 우선순위, 데스크톱·모바일 이미지, 대체 설명, 연결 주소, 닫기·오늘 숨기기.
- 공개 화면: 게시본만 목록·상세·홈·사이트맵에 반영. 광고 표시 및 외부 광고 링크 속성 적용. 기존 공지 주소·언어·목록 페이지 복귀 유지.
- 접근 및 복구: 서버 UID 허용 목록, 동일 출처 검사, 영속 요청 제한, 입력 크기·이미지 검증, 동시 수정 충돌 시 입력 보존, 시간 초과 후 재시도, 로그아웃·권한 상실 시 비공개 화면 초기화.

초안과 게시본의 내용을 분리하고, 편집 revision과 게시 revision도 분리했다. 임시저장만으로 현재 공개 내용이나 배너의 오늘 숨기기 기록이 바뀌지 않는다. 409 충돌은 최신 내용을 덮어쓰지 않는다. 보관 해제만으로 다시 게시하지 않는다.

## 실제 연결 확인

사용자가 지정한 계정이 존재하고 활성 상태임을 확인했다. 해당 UID와 새 요청 제한 비밀값은 무시되는 로컬 환경 파일에만 설정했다. 원본 환경 파일은 복사·수정하지 않았다.

동일 프로젝트의 Firebase 인증으로 임시 검증 세션을 만들고, 관리자 콘텐츠 GET과 기존 접수 목록 GET의 HTTP 200을 확인했다. 콘텐츠 조회에는 기존 공지 19개가 포함됐으며, 브라우저에서도 관리자 메뉴와 서비스 공지 화면이 열렸다. 브라우저 실행 오류와 실제 업무 변경 요청은 없었다. UID·인증 토큰·기존 접수 내용은 이 보고서와 화면 자료에 저장하지 않았다.

실제 콘텐츠 생성·게시·수정·파일 업로드는 실행하지 않았다. 인증 로그인 기록과 읽기 API의 요청 제한 카운터는 조회 과정에서 갱신될 수 있다.

## 운영에 남은 설정

실제 프로젝트의 Cloud Storage 버킷 목록은 0개였고 설정한 버킷의 메타데이터 조회는 404였다. 관리자 API의 `mediaAvailable`도 false이며 화면에서 이미지 업로드를 차단한다. 텍스트 공지와 사이트 상단 텍스트 배너는 이미지 저장소 없이 작성할 수 있다. 홈 이미지 배너에는 저장소가 필요하다.

운영자가 Firebase Storage를 준비하고 서버의 읽기·쓰기 권한을 확인해야 실제 이미지 업로드가 가능하다. 버킷 생성·요금제 변경·운영 환경 설정·배포는 실행하지 않았다. 로컬 관리자 허용 설정이 배포 환경에 자동 적용되지는 않는다.

이미지는 업로드 직후 주소로 열리는 공개 자산이다. 게시 중단이 이미지 주소를 회수하지 않으며, 미사용 업로드 자동 삭제는 포함하지 않는다. 비공개 파일을 올리는 용도로 사용할 수 없다.

상세 데이터 계약·게시 방식·예약 반영 간격·환경 설정은 [운영 가이드](./ADMIN_CONTENT.md)를 따른다.

## 검증 기록

- 전체 단위 테스트: 207개 파일, 1,835개 테스트 통과.
- 전체 ESLint·타입 검사·i18n 문자열 검사 통과. 신규 export 정리와 카드 모양 수정까지 반영한 최종 프로덕션 빌드도 통과.
- 사용하지 않는 신규 export와 중복 별칭을 제거한 뒤 `check:unused`, 관련 서버 테스트 49개, 타입 검사 통과.
- 모의 관리자 브라우저: 23개 화면·12개 흐름 통과. 다섯 관리 화면을 1440·390·320px에서 확인하고, 공지·배너 게시 확인창도 각 너비에서 확인했다. 저장·게시·충돌 복구·탭 이동·예약·이미지·보관/복원·로그아웃·권한 상실과 공개 광고 표시/닫기를 모의 API로 검증했다. 가로 넘침·브라우저 실행 오류가 없었다.
- 모양 검수에서 기존 공통 버튼 CSS가 현황 카드·콘텐츠 목록까지 pill 모양으로 만드는 문제를 발견했다. 해당 영역의 우선순위만 높여 카드 20px·목록 12px로 바로잡고 편집기 관련 테스트 20개와 scoped ESLint를 재실행해 통과했다.
- 공개 회귀 확인: 기존 37개 경로 × 데스크톱/모바일 74개 화면에 영문 홈·목록·상세와 국·영문 404를 더해 총 84개 화면을 확인했다. 넘침·빈 페이지·페이지 응답 5xx·브라우저 실행 오류가 없었다. 기존 국·영문 상세 주소 38개의 제목·언어·canonical·200 응답을 유지했다. 목록 2페이지 → 상세 → 복귀와 없는 공지 → 목록 복귀의 국·영문·너비별 4개 흐름도 통과했다. 범위를 넘는 페이지 999는 마지막 2페이지로 보정했다.
- 공개 API는 국·영문 공지 각 19개와 언어·no-store 헤더를 확인했다. 실게시 배너는 없으며 두 위치의 배너 API가 빈 배열로 200을 반환했다. 기존 셔틀 공급자 API의 502가 두 차례 관찰됐고, 존재하지 않는 일정 방 검증 주소는 예상대로 404였다. 해당 페이지는 계속 사용할 수 있었다. 이번 관리자 기능에서 공급자 로직을 변경하지 않았다.
- 화면 자료에는 모의 관리자와 모의 콘텐츠만 사용한다. 실제 저장·업로드 권한의 성공 증거로 해석하지 않는다.

원시 로그와 모의 화면 자료는 무시되는 `output/playwright/admin-dashboard/`에 보관한다.
