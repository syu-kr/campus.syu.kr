# UI 재사용과 디자인 기준

2026-10-05 기준. 새 화면과 기존 화면을 수정할 때 적용할 기준이며, 모든 기존 컨트롤을 전환한 상태는 아니다.

## 현재 자산과 정리한 문제

기존에 `app/components`의 `Card`, `Modal`, `Icon`, `Container`, `Badge`를 여러 화면에서 재사용하고 있었다. `tailwind.config.js`에는 primary·neutral 색상, 카드 12px·버튼 8px 모서리, 카드 그림자와 글꼴 토큰도 있다. 이 자산과 토큰을 계속 사용한다.

일반 버튼에는 공유 컴포넌트가 없어 페이지별 색·모서리·높이·눌림 효과가 달랐다. 일부 화면에만 뒤로가기 링크가 있었고, 재시도·열기 같은 동작을 밑줄 텍스트로 표시한 곳도 있었다. 이번 정리는 공통 버튼과 전역 상위페이지 이동을 추가하고, 문의·검색·알림·페이지 이동·재시도·룸메이트·시간표·졸업요건·도서관의 주요 액션에 적용한다.

## 일반 액션은 Button 사용

정의는 `app/components/Button.tsx`, 공통 스타일은 `app/globals.css`의 `.ui-button`에 둔다.

| 종류 | 용도 | 기본 표현 |
| --- | --- | --- |
| `primary` | 저장·전송 등 화면의 주요 동작 | 파란 배경, 흰 글자 |
| `secondary` | 취소·재시도·보조 동작 | 흰 배경, 회색 테두리 |
| `ghost` | 닫기·상위페이지 이동 등 가벼운 동작 | 투명 배경, 마우스를 올리면 배경 표시 |
| `danger` | 삭제 등 주의가 필요한 확정 동작 | 빨간 배경, 흰 글자 |

- 최소 높이 **44px**, 모서리 **8px**, 같은 글꼴·간격을 사용한다. 아이콘 전용 버튼은 폭도 44px 이상으로 두고 접근 가능한 이름을 제공한다.
- 마우스를 올리면 배경색이 바뀌고, 누르는 동안 배경색과 1px 이동으로 반응한다. 키보드 `focus-visible`에는 2px 포커스 링을 표시한다.
- 실행할 수 없는 버튼은 네이티브 `disabled`를 사용한다. 흐린 표시와 비활성 커서를 적용하며 클릭과 제출을 막는다. `aria-disabled`만으로 링크 실행이 차단되는 것은 아니므로, 이용 불가능한 이동은 링크 대신 비활성 텍스트로 표시하거나 별도로 실행을 막아야 한다.
- `prefers-reduced-motion: reduce`에서는 전환과 눌림 이동을 제거한다.
- `className`은 `mt-2`, `w-full`, `shrink-0` 같은 배치 조정에 사용한다. 일반 액션의 색·높이·모서리·상태 효과를 화면마다 다시 정의하지 않는다.

```tsx
import Link from "next/link";
import { Button, buttonStyles } from "@/app/components/Button";

<Button variant="secondary" onClick={retry}>다시 시도</Button>
<Button type="submit" disabled={pending}>저장</Button>
<Link href="/campus" className={buttonStyles("ghost")}>캠퍼스</Link>
```

`Button`의 기본 `type`은 `button`이다. 폼 전송은 **`type="submit"`을 명시**한다. 페이지 이동은 `Link` 또는 `<a>`의 의미를 유지하고 `buttonStyles`로 외형만 공유한다. `Button`을 `Link` 안에 넣거나 이동을 일반 버튼의 클릭 이벤트로 대체하지 않는다.

룸메이트 화면의 기존 `primaryClass`·`secondaryClass`는 `RoommateShared.tsx`에서 `buttonStyles`를 참조한다. 네이티브 `<button>`과 링크가 이 스타일을 사용하는 경우도 공통 디자인을 재사용하고 있다.

## 상단 이동은 페이지 구조를 따른다

`Header`는 **홈을 제외한 페이지에서 왼쪽에 상위페이지 이동**을 표시한다. 대상은 `lib/page-navigation.ts`의 `getParentPageHref`에서 정하며, 표시 문구와 링크는 현재 언어를 따른다.

- 학사·캠퍼스·더보기 상세 기능 → 해당 메뉴
- 학교 공지 상세 → 학교 공지 목록, 서비스 공지 상세 → 서비스 공지 목록
- 룸메이트 상세·작성·내 글 → 룸메이트 목록, 이메일 인증 → 캠퍼스
- 학사·캠퍼스·더보기 메뉴 첫 화면 → 홈

이 이동의 목적은 방문 기록에 의존하지 않고 사이트 안의 상위 화면으로 나가는 것이다. 공유 링크로 바로 들어와도 같은 대상이 표시된다. 브라우저의 이전 방문 화면으로 돌아가는 기능과 목적이 다르므로 `history.back()`으로 대체하지 않는다.

본문의 목록·메뉴 링크는 해당 기능을 찾고 이동하기 위한 탐색 요소로 유지한다. 전역 헤더가 있다고 모두 제거할 필요는 없다.

푸터의 문의 항목은 텍스트 형태로 나란히 정렬한다. `사이트 문의하기`는 모달을 여는 네이티브 버튼이지만, `메일로 문의`와 같은 글자색·hover 표현을 사용한다. 공통 액션 버튼의 패딩·배경·최소 높이를 적용하지 않는다. 키보드 초점 표시는 전역 `focus-visible` 규칙을 유지한다.

## 목적에 따라 유지하는 컨트롤과 남은 범위

선택 칩·탭, 달력 날짜, 시간표 격자와 과목 선택, 지도 시설 선택, 본문의 참고 링크는 서로 다른 목적과 상태가 있다. 일반 액션 버튼으로 일괄 바꾸지 않는다. 선택 상태는 `aria-pressed`·`aria-current` 등 해당 의미로 표현하고, 본문 링크의 밑줄은 문서 탐색 표현으로 유지할 수 있다.

이번 변경 이후에도 Meet·알림 및 개인정보·지도·관리자 화면에는 개별 스타일의 일반 액션이 남아 있다. 저장·공유·취소·재시도·새로고침 같은 일반 액션은 해당 화면을 수정할 때 `Button` 또는 `buttonStyles`로 순차 전환한다. 시간표·졸업요건·도서관에서도 특수 선택 컨트롤은 유지한다. 관리자 조치 버튼과 선택용 컨트롤까지 모두 통일했다고 해석하지 않는다.

새 공통 자산은 실제로 같은 목적과 동작이 반복될 때 추가한다. 특수 컨트롤을 포함한 전면 재작성이나 새 UI 의존성 도입은 이 기준의 범위에 포함하지 않는다.

## 이번 변경 검증

최신 `main` 기준으로 로컬 Node 24.18.0·npm 11.16.0·Python 3.13에서 전체 `npm run check`와 `git diff --check`를 통과했다. Windows Python 실행 경로를 현재 검사 프로세스의 PATH에 추가하고, 테스트에는 `VITEST_MAX_WORKERS=2`를 적용했다. 별도 `npm audit --audit-level=moderate` 결과는 취약점 0건이다. 의존성이나 잠금파일 변경은 없다.

최종 전체 검사에 포함된 단위 테스트는 97개 파일·601개 테스트를 통과했다. 빌드와 함께 실행했던 이전 4-worker 재검증에서는 공지 AI 생성 스크립트의 5초 제한 및 임시 폴더 잠금 오류가 한 번 발생했고, 해당 파일 단독 재실행과 최종 전체 재실행이 통과했다. 테스트 제한을 늘리거나 관련 코드를 변경하지 않았다.

로컬 브라우저의 학사일정 화면을 320·390·768·1440px에서 확인했다. 320px 검색 입력 시 초기화 버튼이 화면 밖으로 밀리는 문제를 수정한 후, 검색 입력·초기화와 44px 상단 이동 컨트롤이 화면 안에 표시되는 것을 확인했다. 새 서비스 공지의 최신 목록 노출·상세 본문·상위 목록 이동도 확인했다.

빌드와 브라우저는 공개되지 않는 CI 대체 설정값을 사용했다. 실제 모바일 기기·키보드, 실제 날씨 API와 인증 서비스, 운영 배포 성공을 검증한 결과는 아니다. 공지와 디자인 변경의 운영 반영 여부는 PR 병합·배포 후 확인해야 한다.
